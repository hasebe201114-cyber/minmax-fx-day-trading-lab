# OBS000001 - レンジブレイク・プルバック戦略 v2.1（中期スイング＋両建て）

> 担当: S 戦略チーム → 司令塔提案
> 起票: 2026-08-13
> 状態: 概念設計（v2.1: OBS000004 adversarial レビュー対応 — MT-3 扱いを確定、4 条件 AND に明記）
> バージョン: v2.1（2026-08-13 v2 → v2.1、OBS000004 差し戻し 1 対応）

## 1. 戦略の骨格（1 行サマリ）

**長期方向（D1/W1）に沿って動いている中期レンジ（H4/H1）をブレイクした「後の戻り」を、短期足（M15/M5）で確認してエントリーする。レンジ内では両建てで上下を刈り、ブレイクで勝者側に回転する。**さらに、**ブレイク判定にはレジスタンス/サポートラインの確認を必須**化し、false breakout を一段と排除する。**注文板 / センチメント確認 (MT-3) は DS-8 取得可能時に拡張、現状はフォールバック (恒久的に条件から除外) = 4 条件 AND で駆動**。

## 2. 想定エッジ源

- **false breakout 排除（多段）**:
  1. **レジサポラインの強度判定**（DS-1 から派生）: ブレイクされたラインが「複数回テストされた主要 S/R」であれば、シグナル強度を格段に上げる
  2. **注文板 / センチメント確認**（DS-8、**v2.1: 将来拡張、現状は無効**）: ブレイク方向への注文板厚み（またはトレーダーの同方向ポジション偏り）が確認できれば、ダマシの可能性低下 — **DS-8 が利用可能になるまで本条件は恒久的にフォールバック (passes=True)**
  3. **ブレイク後戻り**（M15/M5）: レンジへの回帰を待つ
  4. **長期方向一致**（D1/W1）: 逆方向ブレイクを排除
- **両建ての刈り取り**: レンジ相場でも上限・下限の往復で小さく利益確定
- **リスクリワードの非対称化**: エントリー根拠が「LT 方向 + MT ブレイク + S/R + ST 戻り」の **4 条件 AND**（v2.1 で MT-3 を恒久的に除外）で、勝率は 50% 程度でもペイオフレシオ 2:1 以上を狙う

## 3. 時間軸階層

| レイヤ | 足 | 役割 | 主な指標 |
|---|---|---|---|
| **LT（長期方向）** | D1 / W1 | トレンド方向の判定 | MA(50)/MA(200) の位置関係、ADX、ローソク足の方向性 |
| **MT（中期レンジ + ブレイク判定）** | H4 / H1 | レンジ上限・下限の決定、ブレイクの強度判定 | Donchian、BB、ATR、**レジサポライン（DS-1 から派生）**、**注文板 / センチメント（DS-8）** |
| **ST（エントリー）** | M15 / M5 | 戻り確認の執行タイミング | ピンバー、包み線、エンゲル、ストキャス RSI のダイバージェンス |

**ホールド期間**: 数日〜数週間（中期スイング）。日中デイトレードはしない。

## 4. ステートマシン（v2 拡張）

```
       [レンジ形成中]
              │  H4 終値がレンジ上限を更新
              ▼
       [上限ブレイク検出]  ※ ここから MT の 3 サブ条件判定
              │
              ├─── MT-1: Donchian / BB ブレイク成立
              ├─── MT-2: レジサポライン強度 ≥ 閾値（直近 1年で 3回以上テスト / 丸目 / フィボ 0.5 / 0.618 等）
              ├─── MT-3: 注文板（DS-8）buy 側厚み ≥ 閾値、またはセンチメント long% ≥ 閾値
              │
              │  3 サブ条件 AND
              ▼
       [強いブレイク]   ※ MT サブ条件 1 つでも欠ける → 「弱いブレイク」と判定しスルー
              │  価格が一時的に戻る
              ▼
       [戻り待ち] ─────── 戻らず継続 → [トレンド継続・追撃なし]
              │  戻り完了
              ▼
       [戻り確認]  ← M15/M5 で反発シグナル発生 + LT 方向一致
              │
              ▼
       [ロング実行]   ※ レンジ下限ブレイク・LT 下降方向ならショート実行
              │
              │  次のレジスタンス到達 / 損切り / LT 方向転換
              ▼
       [ポジション解消]
              │
              ▼  新レンジ形成
       [レンジ形成中] へ戻る
```

### 4.1 弱いブレイクの判定

MT の 3 サブ条件のうち、1 つでも欠ける場合は「弱いブレイク」と判定し、**エントリーを見送る**。これにより:
- Donchian を抜けただけの「にせブレイク」を 30-50% 削減
- S/R ラインの重要度が低いブレイクを排除
- 注文板の薄い（=大口が逆張りしている）ブレイクを排除

## 5. エントリー・手仕舞いルール

### 5.1 エントリー条件（**4 条件 AND**、v2.1 で MT-3 を恒久的に除外）

> v2.1 変更点: 従来「5 条件 AND」と記載していたが、MT-3 (注文板/センチメント) は DS-8 が GMO コイン外国為替FX API で未取得のため、恒久的にフォールバック (passes=True) となり実質機能していない。OBS000004 adversarial レビュー指摘を受け、**4 条件 AND に確定**。MT-3 は DS-8 が利用可能になった段階で再有効化 (→ 5 条件 AND 復帰)。

1. **LT 方向**: MA(50)/MA(200) で長期方向を判定、ブレイク方向と一致すること
2. **MT-1 レンジブレイク**: 直近 N 本の H4 高値（または安値）を終値でブレイク
3. **MT-2 レジサポライン**: ブレイクされたレベルが、過去 1 年で 3 回以上テストされた主要 S/R ライン
4. **ST 戻り確認**: ブレイクレベルへの戻りを確認するシグナル（ピンバー / 包み線 / ダイバージェンス）

> (v2 旧 MT-3 注文板 / センチメント: 現状は恒久フォールバック。DS-8 利用可能時に再有効化)

### 5.2 損切り

- ブレイクレベル ± 1 ATR（H4 基準）
- 逆方向ブレイク発生（M15 で再ブレイク）
- (v2 旧) 注文板センチメントが反転したら損切り検討 — **v2.1 で MT-3 恒久フォールバック化により、現状は本トリガーは無効**

### 5.3 利食い

- 第一目標: リスクリワード 2:1
- 第二目標: 次の H4 レジスタンス / サポート（次の S/R ライン）
- トレーリング: 1R 達成後は MA(20) on H4 をトレイル

### 5.4 両建てロジック（レンジ内）

- レンジ上限 − 0.5 ATR に **sell limit**
- レンジ下限 + 0.5 ATR に **buy limit**
- 両方成立 → 両建て状態
- 強いブレイク発生時: ブレイク方向の注文は維持、反対側は 1R 達成で利確 / ブレイク方向と逆行したら損切り
- 弱いブレイク発生時: 両建て状態を維持、レンジ継続とみなす

## 7. 想定エッジケース・既知の懸念

| # | 懸念 | 対応 |
|---|---|---|
| C1 | レンジが小さすぎ → ブレイク頻発でダマシ多発 | MT レイヤで最低レンジ幅 = 1 ATR 以上を制約に追加 |
| C2 | レンジが長大化 → 両建ての含み損増大 | 両建ての最大保有期間 = 20 営業日 / 含み損 = 証拠金の 5% で強制解消 |
| C3 | 経済指標急変でスプレッド拡大 → 想定外のスリッページ | 経済指標 ±30 分は新規エントリー禁止（DS-3 で自動フィルタ） |
| C4 | 長期方向の判定遅れ → レンジ→トレンドへの切り替わりで反対ポジションが残る | LT レイヤの MA(50)/MA(200) クロスで両建て強制解消 |
| C5 | 通貨間の相関が高すぎて「5 通貨分散」が効かない | DS-1 取得後に相関マトリクスで事前検証（相関 ≥ 0.8 のペアは同時エントリーしない制約） |
| **C6** | **GMO のリテール FX で注文板深度データが取得できない** | DS-8 は GMO 公式で取得可能な範囲のみ（top-of-book bid/ask、トレーダーセンチメント）。**v2.1: DS-8 が利用可能になるまで MT-3 は恒久的にフォールバック (passes=True) = 4 条件 AND で駆動**。実装は `multi_timeframe.py:218-220` の `OrderBookSignal(available=False, ..., passes=True)` |
| **C7** | **レジサポラインの過剰検出（ノイズ多数）** | 直近 1 年で 3 回以上テスト + ATR 0.5% 以内の接触のみを主要 S/R と認定。フラクタル検出は 5 本窓で十分大きいピボットのみ採用 |
| **C8** | **注文板 / センチメントの代理指標が FX で誤差大きい** | **v2.1: MT-3 を恒久的に条件から除外し、4 条件 AND (LT + MT-1 + MT-2 + ST) で確定**。MT-3 を満たさずともエントリー可という旧 C8 の「重み付け判定」は解消。DS-8 利用可能時に 5 条件 AND 復帰 |

## 8. バックテスト計画

- **期間**: 2020-01 〜 2025-12（5 年、レジーム 4 種: コロナショック / インフレ加速 / 利上げサイクル / レンジ安定）
- **データ粒度**: M5 足（最低 5 年分、1 通貨ペアあたり約 150 万行）
- **通貨**: 5 通貨（OBS000002 で選定: USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD）
- **ウォークフォワード**: train 2 年 → test 1 年 のローリング 3 分割
- **KPI 計算**: 期間別・通貨別・市場レジーム別（LT 方向転換点ベース）
- **DS-8 の取り扱い**: 過去データがあれば実測値、なければセンチメントの代理指標または MT-3 をスキップしてフォールバック評価

## 9. フォワードテスト計画

- **期間**: 6 ヶ月（30/60/90 日チェックポイント）
- **方法**: ペーパートレード（GMO テストネットがあれば優先、なければ 0.5 pip 固定フォールバック）
- **判定**: 月次シャープ ≥ 0.4、最大 DD ≤ 10%、Profit Factor ≥ 1.2

## 10. 採用後の実行基盤

- **接続先**: trading-app-v2 の FX モジュール新設、または本PJ内 `src/execution/`
- **執行方式**: 指値（戻り確認）と逆指値（ブレイク確認）のハイブリッド
- **両建て管理**: 同時両建てポジションの証拠金消費を内部で監視
