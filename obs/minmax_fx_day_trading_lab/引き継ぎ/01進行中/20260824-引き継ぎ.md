## 重要な懸案（次セッションが引っかかりやすい点）

### 1. SYS-FX022のライブ監視は「デプロイ待ち」で止まっている

3つの自動実行方式を試して、すべて実運用に耐えないと判明した:

| 方式 | 結果 |
|---|---|
| Claude使い捨てセッションRoutine（`create_new_session_on_fire`） | 発火は記録されるがgit pushが完了しない（**原因未特定**） |
| GitHub Actions（`.github/workflows/live-ticker-poll.yml`） | 無料枠超過で即時失敗（課金契約が必要、司令塔確認済み） |
| Firebase Cloud Functions（`functions/index.js`、司令塔提案） | **実装完了、コードは動作確認していない（構文チェックのみ）。デプロイには司令塔側のFirebase/GCP CLI操作が必要（このセッションにはFirebase認証情報が無い）** |

次セッションで最初に確認すべきこと: **Firebase Cloud Functionsはデプロイされたか？** されていれば`data/raw/live-ticker/`に新しいコミットが定期的に増えているはずなので`git log -- data/raw/live-ticker/`で確認する。されていなければ、`functions/README.md`の手順（GitHub PAT発行→Secret登録→`firebase deploy`）を司令塔に案内する。

デプロイされるまでの間、`poll_ticker.py`・`reconcile_divergence.py`はセッション起動時に手動実行するしかない（`PYTHONPATH=src python3 scripts/live_monitor/poll_ticker.py`）。

### 2. SYS-FX012週次フォワードテストRoutineは信用できない

`trig_01XuLkqxjKp9WaigqH5W87Z2`（「SYS-FX012 フォワードテスト週次サイクル」、2026-08-22設定、`scripts/forward_test/weekly_cycle.py`を毎週月曜実行）は、`list_triggers`で見ると**`last_run.status`が`ROUTINE_RUN_STATUS_SUCCEEDED`（2026-08-24 00:11〜00:13、約2分19秒稼働）と表示される**のに、実際には`sysfx012_forward_test_ledger.json`が2026-08-22 20:43から更新されていなかった。つまり「Routine自体は正常終了と判定されている」のに「実データへの反映が起きていない」という、単純な失敗より診断が難しいパターン。**このRoutineが動いているという前提を置かず、フォワードテストの最新状態を確認したいときは`git log --oneline -- research/method-notes/sysfx012_forward_test_ledger.json`で最終コミット日時を必ず確認し、古ければ`PYTHONPATH=src:scripts python3 scripts/forward_test/weekly_cycle.py`を手動実行すること。**

原因はSYS-FX022の調査で判明したClaude Routineのgit push不具合と同一と考えられるが未確定。このRoutine自体を無効化するかどうかは司令塔判断待ち（放置していても実害は無いが、「動いているはず」という誤った前提を生みやすい点に注意）。

### 3. mainに軽微な検証用コミットが残っている

コミット`096a21b`（メッセージ「test: スクラッチクローンからのpush検証(すぐrevertされる)」）が`main`に残っている。中身は実際のライブティックデータ4行で無害だが、メッセージが「revertされる」と書きつつ実際にはrevertしていない。実害はないため放置で問題ない（説明のためここに記録）。

### 4. GitHub Actionsワークフローファイルは削除していない

`.github/workflows/live-ticker-poll.yml`は動かない状態のまま残してある（司令塔が将来GitHub Actionsの課金プランを契約した場合に備えて）。存在自体に副作用は無い。
