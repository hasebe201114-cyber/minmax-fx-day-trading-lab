# PJ000004 - 基本データ層と検証プロセス定義（minmax-fx-day-trading-lab）

> 担当: A 設計チーム（spec 確定）+ S 戦略チーム（プロセス監督）
> lp-strategy-lab の PJ000004 相当のドキュメント。本PJ固有の品質ゲート Q1〜Q8 とデータ層を定義する

## 1. 背景

LP 戦略ラボでは「データの壁」（DS-1〜DS-6 の精度不足が複数実験の判定を覆した事例）から、検証プロセス自体を再設計する PJ000004 を実施した。FX デイトレードでも同等のリスクがあるため、**プロジェクト起票と同時に**データ層と品質ゲートを明文化する。

## 2. データ層（DS-FX シリーズ）

| ID | 名称 | 主ソース | 検証粒度 | 必須度 |
|---|---|---|---|---|
| **DS-1** | 通貨ペア × 足種 × 期間の OHLCV | dukascopy / histdata.com / GMO API | 3年 / 1分足以上 | 必須 |
| **DS-2** | スプレッド時系列（ティック or 1分粒度） | GMO 実測 | 6ヶ月 / 1分粒度 | 必須 |
| **DS-3** | 経済指標カレンダー + 発表時刻周辺挙動 | investing.com / ForexFactory | 3年 / イベント単位 | 必須 |
| **DS-4** | セッション境界時刻 + 典型ボラ/出来高 | 自前集計（DS-1 から派生） | 3年 / 1時間粒度 | 必須 |
| **DS-5** | スリッページ代表性データ | GMO テストネット or 0.5 pip 固定フォールバック | 100注文以上 | 必須 |
| **DS-6** | GMO コイン API 仕様 | GMO 公式ドキュメント | n/a | 必須 |
| DS-7 | （将来）代替ブローカー仕様（OANDA / IBKR） | 公式 | n/a | 将来 |

## 3. 品質ゲート Q1〜Q8

### Q1: データ欠損の網羅的検出
- 1分足について全カレンダー日から**価格パスの欠損**を検出
- 経済指標発表時刻の周辺 ±30 分に欠損があれば警告
- 週末/祝日の正常な欠損は除外

### Q2: ウォームアップ期間の前倒し
- 移動平均/RSI 等のインディケータは計算に N 期間必要
- **検証区間の最初の N 期間は必ずウォームアップ**として結果から除外
- ウォームアップを除外しない実装は差し戻し

### Q3: 平滑化系列の併記
- 生の OHLC に加え、ATR/ADX/標準ボラ等の平滑化系列を併記
- 単一指標のみの K ゲートは不可

### Q4: implied コスト（スプレッド + スリッページ）の自動反映
- バックテストは**成行で約定したと仮定 + スプレッド + 0.5 pip スリッページ**を毎回課す
- `params.json` で cost_pips_per_side = 0.5 を明示
- cost_pips_per_side = 0 は差し戻し

### Q5: データソース/取得日の記録
- `data/curated/*.json` の各ファイルに `source` / `fetchedAt` を必須記載
- `data/MANIFEST.json` で全データ系列を一元管理

### Q6: 通貨ペア単位の decimals 整合性
- USD/JPY は 0.001、EUR/USD は 0.00001 等、JPY 系と非 JPY 系で桁数が異なる
- ロットサイズ・P/L 計算時の桁数誤差を CI で検出

### Q7: 当日クロースの保証（デイトレード固有）
- 検証区間内のすべてのトレードは**必ず日本時間でその日の 06:00 までに手仕舞い**（または対応するセッションクローズ時刻）
- それ以降にクローズされたトレードが含まれていれば差し戻し
- 週末持ち越しは絶対禁止

### Q8: ブローカー仕様の整合性（デイトレード固有）
- 通貨ペアの取扱状況が GMO コイン 21 ペアに含まれているか
- 取引単位（最小/最大ロット）、スプレッド、レバレッジ、API rate limit が spec と一致するか
- API 仕様変更時の追跡可能性（`data/curated/ds-6-api-spec.json` の fetchedAt）

## 4. 検証プロセス

### Phase 1: データ基盤（DATA-FX チケット）
- 目的: DS-1〜DS-6 を取得・検証・カタログ化
- 担当: A 設計（spec）→ B 実装 → C 品質（DATA モード）
- 完了条件: 全 Q1〜Q8 合格、`data/curated/*.json` 実体化、`MANIFEST.json` 完成

### Phase 2: 戦略 prescreen
- 目的: SYSTEMS.md の各 SYS について GO/PAUSE を S が断じる
- 成果物: `research/EXP-FXxxxxx/00-prescreen.md`

### Phase 3: 詳細 spec 確定
- 目的: K1d〜K6d の閾値を**バックテスト結果を見る前に**固定
- 成果物: `research/EXP-FXxxxxx/00-spec.md`

### Phase 4: バックテスト → フォワードテスト → 採用判定
- 目的: 6ヶ月バックテスト + 30/60/90 日フォワードテスト
- 成果物: `research/EXP-FXxxxxx/10-result/` 配下、20-c-review.md、30-decision.md
