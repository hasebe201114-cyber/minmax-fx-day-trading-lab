# PJ000001 - minmax-fx-day-trading-lab プロジェクト方針

> 担当: 司令塔（ユーザー）+ S 戦略チーム
> 目的: 「FX マルチタイムフレーム・中期スイング戦略を、5年バックテスト + 6ヶ月フォワードテストで定量的に検証する」ラボの全体方針

> **2026-08-13 方針変更**: 当初「デイトレード縛り」で起票したが、司令塔からの中期スイング戦略方針（両建て運用あり・長期方向 + 中期レンジ・ブレイク後の戻りエントリー）に合わせて、**スコープを「マルチタイムフレーム・中期スイング + 両建て」に拡張**。詳細は OBS000001 / SYSTEMS.md / STRATEGY-BRIEF.md を参照。

## 1. ゴール（北極星 KPI）

**「GMO コイン 外国為替FX API を使い、最大 5 通貨のマルチタイムフレーム中期スイング戦略で、6ヶ月間のフォワード検証において、月次シャープレシオ 0.4 以上かつ月間最大 DD 10% 以下を維持できる、自動売買戦略ポートフォリオを 1つ以上構築し、本番運用にGOを出すこと」**

補助 KPI:
- 月次 Profit Factor > 1.2
- 月次期待値 > 0 円
- ペイオフレシオ ≥ 1.5
- 最大連続損失 ≤ 5 トレード
- バックテスト ↔ フォワードテストの乖離率 ≤ 30%
- 両建て状態の最大証拠金消費率 ≤ 30%

## 2. スコープ

### In Scope
- **通貨ペア**: 最大 5 通貨（OBS000002 で選定、暫定案 A: USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD）
- **時間軸階層**:
  - LT（長期方向）= D1 / W1
  - MT（中期レンジ）= H4 / H1
  - ST（エントリー）= M15 / M5
- **ホールド期間**: 数日〜数週間
- **週末持ち越し**: 禁止（土曜 06:00 JST までに全決済）
- **戦略カテゴリ**: レンジブレイク・プルバック（OBS000001 / SYS-FX007）、トレンドフォロー、長期方向フィルター合成、スワップ最適化、両建て・グリッド系
- **検証**: 5年バックテスト（2020-2025、4 レジーム = コロナショック / インフレ加速 / 利上げサイクル / レンジ安定）+ 6ヶ月フォワードテスト（ペーパートレード or テストネット）
- **両建て**: 同時両建てポジションの証拠金消費を内部で監視
- **ブローカー**: GMO コイン外国為替FX を主、副候補として OANDA Japan / IBKR
- **コスト**: 通貨ペア別スプレッド、API 手数料 0.002%、スリッページ 0.5 pip、**スワップポイント両側発生**

### Out of Scope
- 暗号資産の FX 派生（USD-M Perpetual 等は対象外）
- ポジショントレード（数ヶ月単位の長期保有）
- マクロ経済指標の長期的テーマ
- 流動性プール（lp-strategy-lab 側）
- 純裁量トレードの記録・再現
- 純スキャルピング（数分以下のホールド）

## 3. 戦略間の比較可能性

複数の戦略カテゴリ（レンジブレイク・プルバック / トレンドフォロー / 長期方向フィルター合成 等）を 1つの共通 KPI フレームワークで評価し、**「どの戦略カテゴリが GMO コインの 5 通貨で生き残るエッジを持つか」を探索的に比較する**。最終的に**採用戦略群はポートフォリオ合成**（トレンドフォロー + レンジブレイク・プルバックのような負の相関ペア）を目指す。

これは lp-strategy-lab の方針 §3「戦略カテゴリ間で成績を横並びに比較できる」を踏襲。

## 4. データ要件

### DS-FX シリーズ（DATA チケットで管理）
- **DS-1**: 通貨ペア × 足種 × 期間の OHLCV データ（5 通貨 × LT/MT/ST 3 階層 × 5 年 = 75 シリーズ）
- **DS-2**: スプレッド時系列（ティックレベル or 1分粒度。GMO 実測）
- **DS-3**: 経済指標カレンダー（米雇用統計 / 日銀会合 / ECB 理事会等）+ 発表時刻周辺のティック挙動
- **DS-4**: セッション境界時刻（東京/ロンドン/NY 開始）と各セッションの典型的なボラ/出来高
- **DS-5**: スリッページの代表性データ（成行注文の slippage 実測 or 0.5 pip の固定フォールバック）
- **DS-6**: GMO コインの API 仕様（rate limit, 注文タイプ, 取引単位, 最小ロット, 取扱ペア一覧）
- **DS-7**（新）: 通貨ペア別スワップポイント時系列（両建ての正味コスト計算用）

### データ取得方針
- 履歴 OHLC: GMO コイン REST API（`/public/v1/klines` 等）または dukascopy / histdata.com 等の公開アーカイブ
- ライブ検証: GMO テストネット or ペーパー口座
- 経済指標: investing.com / ForexFactory のカレンダー
- スワップポイント: GMO 公開値（日次更新）

## 5. 検証プロセス（4 フェーズ）

### Phase 1: データ基盤構築
DATA チケット（`research/DATA-FX001/`）で DS-1〜DS-7 を整備。品質ゲート Q1〜Q9 を LP ラボから拡張流用:
- Q1: データ欠損の網羅的検出
- Q2: ウォームアップ期間の前倒し
- Q3: 平滑化系列の併記
- Q4: implied コスト（スプレッド + スリッページ）の自動反映
- Q5: データソース/取得日の記録
- Q6: 通貨ペア単位の decimals 整合性
- Q7: **週末持ち越し禁止の保証**（土曜 06:00 JST までに全決済）
- Q8: **両建ての証拠金消費追跡**（同時の buy + sell ポジションを正しく記録）
- Q9: **スワップポイント両側反映**（両建て時の正味コストを計算）

### Phase 2: 戦略候補の prescreen
SYSTEMS.md の各 SYS について `00-prescreen.md` を起票し、**GO/PAUSE** を戦略チーム（S）が断じる。**最初の対象は SYS-FX007**（OBS000001 / レンジブレイク・プルバック）。

### Phase 3: 詳細 spec 確定 → バックテスト
`00-spec.md` で**試算前に評価基準を数値で固定**。HARKing 防止のため、K1m〜K7m の閾値を**バックテスト結果を見る前に** spec に転記する。

### Phase 4: フォワードテスト → 採用判定
ペーパートレードまたは少額実弾で 30/60/90 日のチェックポイントを通過し、C 品質チームの adversarial review を経て、司令塔 GO が出たら trading-app-v2 系（または本PJ内 execution モジュール）へ統合。

## 6. 採用戦略の本番接続

採用判定が下った戦略は、以下のいずれかの経路で実行環境へ接続する：

- **経路 A**: trading-app-v2 内に FX モジュールを新設して統合（BTC キャリと並列運用）
- **経路 B**: 本PJ内に `src/execution/` モジュールを新設し、GMO コインと直結（独立運用）

現時点ではどちらの経路も未確定。**最初の戦略が採用された時点で S が司令塔へ具申する**。詳細は PJ000001 §6 を参照（PJ000001 v2 で更新予定）。

## 7. リスク・制約

- **GMO コイン 30日間無料トライアルの終了**: 終了後は API 手数料 0.002% が実質的に適用される。Profit Factor 1.2 以上の戦略はこれを吸収できる水準を最初から要求する
- **スリッページ**: 成行注文の slippage は 0.5 pip を保守的仮定で固定。フォワードテストで乖離が見られたら Q 経由で spec を再校正
- **GMO サーバー障害**: API 切断時のポジション保持リスク。週末持ち越し禁止により土曜早朝までのリスクは限定的だが、サーバー障害で強制クローズできない場合の最大エクスポージャーを別途評価
- **税制**: FX の利益は申告分離課税（税率20.315%）。バックテストの純利益は税引き後で表示
- **法規制**: 金融商品取引法・外為法上のポジション上限報告（10億USD超）等
- **両建ての証拠金管理**: 同時両建て時の証拠金消費率が 30% を超えないよう内部で監視
- **スワップポイント変動**: 通貨間の金利差政策変更でスワップが急変するリスク。フォワードテストで監視

## 8. 完了条件

この PJ000001 は以下のいずれかで「完了」とする：

- (A) 6ヶ月フォワードテストでゴール KPI を達成し、本番運用へ GO が出た
- (B) 6ヶ月間検証した結果、GMO コインの 5 通貨で再現性のあるエッジが見つからず、「FX 中期スイング自動売買は現時点で不採用」と結論した（lp-strategy-lab での「不採用」と同等）

(A) または (B) のいずれかで ゴール達成となる。不採用の結論を出すこと自体も重要なゴール。
