## 2. 第1試行の設計（**結果を見る前に固定**）

### 何を1つだけ変えるか

**戦略X を差し替える。** SYS-FX011 trailonly版（ペイオフ Train 1.09 / Validation 1.21）に代えて、**SYS-FX018 で確定済みの `breakeven_trigger_r = 2.0` 版**（＝SYS-FX012 候補①の設計に建値移行トリガー 2.0R を適用したもの）を使う。

- 戦略Y（SYS-FX024 R-A）は**一切変更しない**
- 配分ウェイト 50:50 も**一切変更しない**
- **新規パラメータの導入はゼロ**。`breakeven_trigger_r = 2.0` は EXP-FX000012（SYS-FX018）で 2026-08-23 に確定済みの値をそのまま流用する

### なぜこの差し替えか（根拠と、正直な留保）

SYS-FX018 の Train 実測は次のとおり記録済みである（`research/method-notes/sysfx018_breakeven_sweep_trainonly_backtest.json`、2026-08-23）:

- **ペイオフレシオ 1.549 — K4m 基準（1.5）を本プロジェクトで初めてクリア**
- perm_p 0.044（有意）、必須KPI 7/9
- **実効n 219 のみが 300 に未達**で、単独では選定ルールから外れた

**合成では実効n が制約でなくなる**（ベースライン合成の実効n は Train 1,330・Validation 474）。すなわち、**SYS-FX018 が単独で落ちた唯一の理由（n不足）を合成が解消し、合成が落ちている理由（ペイオフ不足）を SYS-FX018 が解消しうる**。互いの弱点が噛み合う関係にある。

**正直な留保**: 「合成のペイオフが未達だったから、ペイオフの高い構成要素に差し替える」という発想自体は**結果を見てから選んでいる**。ただし (a) SYS-FX018 のペイオフ 1.549 は5日前に別EXPで確定済みの事実であり本EXPのために探索した値ではない、(b) 新規パラメータをゼロにしている、(c) 本試行の判定基準を実行前に本amendmentで固定している、という3点で HARKing のリスクを抑える。**それでも「後付けで良い部品を選んだ」側面が残ることは記録しておく。**

## 3. 選定ルール（**結果を見る前に固定**、親spec §4 を踏襲）

1. P1 について、Train・Validation の両方で3段階判定（再現した / 部分的 / 再現せず）を行う
2. **Validation で「再現した」かつ必須9項目すべて達成** → ポートフォリオ採用候補として司令塔に具申
3. **Validation で「再現した」が必須ゲート未達** → 未達項目を明記し、改善ループ第2試行（最後の1回）へ
4. **Validation で「部分的」または「再現せず」** → P0 に劣ると判定し、**P0 の結果（7/9）を最終結論として扱う**
5. **未達項目を見てから閾値・ウェイト・KPI定義を変更しない**

## 4. 想定される失敗モード（結果を見る前の正直な記録）

1. **ペイオフは改善するがトレード数が減る。** breakeven=2.0 は建値移行を遅らせるため勝ちトレードが伸びる一方、SYS-FX018 の Train 実効n は 219（trailonly版の 300 から27%減）だった。合成後の実効n が 300 を割る可能性がある
2. **permutation 有意性は改善しない可能性が高い。** 週ブロックのクラスタ数（Validation で約35週）が本質的な制約であり、トレードの中身を変えても独立情報量は増えない。**この項目は検証期間の拡張（EXP-FX000020）でしか解決しない見込み**
3. **SYS-FX018 の Validation は未実施**である。Train のペイオフ 1.549 が Validation で再現する保証はない
4. 合成後のペイオフは両戦略の加重平均に近くなるため、戦略Y のペイオフ（0.69前後）に引き下げられ、**1.5 に届かない可能性が依然として高い**

### 解釈（正直な記録） — §4 の失敗モード予想が2つとも的中した

- **失敗モード #1「ペイオフは改善するがトレード数が減る」が的中。** 戦略X のトレード数は Validation で 133件 → **61件**（54%減）、合成の実効n は 474 → 402
- **失敗モード #4「合成後のペイオフは戦略Y に引き下げられ 1.5 に届かない」が的中。** 戦略X 単独のペイオフは Validation で **2.127** と極めて高いにもかかわらず、**合成後は 1.193 にしかならない**。理由は明快で、合成トレード列は戦略Y（Validation 341件）が戦略X（61件）を件数で圧倒しており、**Y の「高勝率・低ペイオフ」プロファイルが支配する**ためである

### ここで判明した構造的な事実（重要）

**グリッド（戦略Y）を含む限り、ペイオフレシオ ≥ 1.5 は構造的に達成できない。** これは結果から言っているのではなく、設計から確定的に言える。`research/EXP-FX000018/00-spec.md` §6.1 で既に論証したとおり、グリッドは利確が「1刻み」・損切りが「最大N刻み」という非対称構造を持ち、**R単位のペイオフが 1.5 を超えることは設計上あり得ない**。その戦略を件数で支配的な比率で合成に含めれば、合成のペイオフも同じ天井に縛られる。

一方、**合成のPFは Train 1.539・Validation 1.645 でいずれも 1.5 以上**である。EXP-FX000018 §6.1 では、この構造的制約を理由に K4m を「勝率中立版の PF ≥ 1.5」へ置換することを**結果を見る前に**宣言し、その根拠（勝率50%ではペイオフ1.5 ⟺ PF 1.5）を示した。**同じ論理は、グリッドを含む合成にもそのまま当てはまる。**

**ただし本EXPでは、この置換を自分の判断で適用しない。** 親spec §3.3 は「単独戦略と同じ必須ゲートをそのまま適用する（緩めない）」と結果を見る前に固定しており、**未達を見てからゲートを置き換えるのは、たとえ論理が正しくても手続き上 HARKing に該当する**。置換の可否は司令塔判断事項として §7 に上げる。

### 残る2つの未達ゲートの性質（切り分け）

| 未達項目 | 性質 | 解決経路 |
|---|---|---|
| **ペイオフレシオ 1.193 < 1.5** | **構造的**。グリッドを含む限り達成不可能 | 戦略設計では解決しない。**KPI定義の問題**（司令塔判断） |
| **perm_p（週ブロック）0.1459〜0.2028 < 0.05** | **サンプル数の問題**。Validation の独立クラスタは約35週しかなく、トレードの中身を変えても独立情報量は増えない | **検証期間の拡張（EXP-FX000020）でしか解決しない** |

**どちらも「戦略の作り方」では解決しない。** 第1試行はこのことを実証的に示した点に価値がある。

## 6. 判定

**第1試行は改善をもたらさなかった（Validation 7/9、P0 と同数で他指標は劣位）。改善ループ 1/2 を消化（残り1回）。**

**採用候補は引き続き P0（戦略X = SYS-FX011 trailonly、Validation シャープ 2.565・最大DD 3.60%・必須KPI 7/9）とする。**

## 7. 次のアクションと司令塔への確認事項

改善ループの最後の1回（第2試行）は、上表のとおり**「サンプル数の問題」を直接叩く以外に筋の良い手が残っていない**。したがって:

- **第2試行は、EXP-FX000020（検証期間の5年拡張）で拡張データが揃った後に、同じ P0 構成のまま拡張期間で再評価する**こととし、本amendmentの時点では消化しない（拡張データの取得完了待ち）
- **司令塔への確認事項**: グリッドを含むポートフォリオに対して、K4m（ペイオフレシオ ≥ 1.5）を EXP-FX000018 §6.1 と同じ論理で **PF ≥ 1.5 へ置換してよいか**。置換が認められる場合、P0 の Validation は **8/9**（残る未達は permutation 有意性のみ）となる。認められない場合、ペイオフゲートは構造的に達成不可能であるため、グリッドを含む合成は永久に採用不可となる

## 7.1 司令塔回答と最終結論（2026-08-28、EXP-FX000020経由）

§7 の確認事項は EXP-FX000020 §10.7 で拡張Train評価とあわせて再上程し、司令塔から回答を得た（詳細: `PJ000004` Q14、`EXP-FX000020/00-spec.md` §10.8）。

- **K4m→PF置換は承認**。SYS-FX025 限定ではなく、グリッドを含む合成戦略全般の恒久ルールとして採用
- **一方でK5m（スプレッドコスト倍率≥3.0）は維持**と決定された。判定に用いる保守的コスト水準（×2.0）ではSYS-FX025のPFも1.379と置換後の基準1.5に届かないため、**置換の可否に関わらずSYS-FX025の最終分類は変わらない**

**最終判定（P0改定）**: SYS-FX025（P0 = SYS-FX011 × SYS-FX024 R-A の等ウェイト合成）は**REJECT確定**。拡張Train・Validationのいずれにおいても、K5mと（保守水準での）ペイオフ/PF・permutation週ブロックが未達のまま残る。改善ループ第2試行（拡張期間でのP0再評価）はEXP-FX000020 §10で実施済みであり、結果は不変（REJECT）だったため、これ以上のループは消化しない。
