## 0. 一行要約

**H1足で「異常に大きなブレイク」が起きたら、そのトレンドをM5足のダウ理論で追跡し、
押し目（戻り）ごとに1通貨1ポジションで順張りエントリーし、幅の広いATRトレーリングで
伸ばしきる。トレンドの型が崩れたら追跡終了。**

SYS-FX011 との違いは**出口だけ**（トレール幅 1.0倍 → **3.0倍**、リスク率 1.00% → **0.65%**）。
エントリー条件は完全に同一である。

## 2. トレンドイベントの検出（H1、エントリーの前提条件）

### 2-1. ブレイク判定

各H1バーについて次を計算する。

```
ratio = (H1バーの高値 − H1バーの安値) ÷ ATR(H1, 14, Wilder)
```

- **`ratio ≥ 3.5` なら「ブレイクイベント」**（定数 `N_BREAKOUT = 3.5`）
- **方向**: そのH1バーが陽線（終値 > 始値）なら **UP**、そうでなければ **DOWN**

> 3.5 という値は「週1回程度の発生頻度」を狙って Train から導出した
> （`derive_vol_breakout_entry_params.py`）。

### 2-2. 重複イベントの間引き（dedup）

同一方向のブレイクが連続して発生した場合、**先行するイベントの追跡期間と重なるものは
新規イベントとして扱わない**（`select_non_overlapping_breakout_events()`）。

> これは外部レビュー対応（T-01〜T-03）で発見・修正した**重複トレード生成バグ**への恒久対策。
> 修正前は同じ値動きから複数のトレードを生成し、Test期間の利益の36.4%が重複計上だった。

### 2-3. ショック抑制フィルター（価格反応型）

**複数通貨で同時にブレイクが発生している時間帯は、新規エントリーを見送る**
（`price_shock_filter.make_price_shock_check()`）。

- 目的: 地政学ショック・要人発言など、通貨固有ではない市場全体の急変時に
  連敗クラスタが発生するのを抑える（2025-06-13 のイラン攻撃時に実際に発生）
- **カレンダー（経済指標日時）は使わない**。値動きだけで判定する
- 値動きが沈静化すればエントリーを再開する
- **トレンドの構造追跡（ダウ理論の型崩れ判定）自体は抑制中も継続する**

## 3. エントリー（M5、ダウ理論の押し目/戻り）

ブレイクイベントが確定したら、そのH1バーの**次のM5バー**から追跡を開始する。

### 3-1. スイング構造の追跡

M5足に **ZigZag（閾値 = 1.0 × ATR(M5, 14)）** を当て、スイング高値・安値を認識する。

### 3-2. エントリー条件

| 方向 | エントリー条件 |
|---|---|
| **UP（押し目買い）** | 直近スイング安値（Higher Low）を形成した後、上方向へ切り返したことをM5終値で確認 |
| **DOWN（戻り売り）** | 直近スイング高値（Lower High）を形成した後、下方向へ切り返したことをM5終値で確認 |

- **1通貨1ポジション制約**: すでにその通貨でポジションを保有している間は新規エントリーしない。
  **決済後、トレンドが継続していれば次の押し目で再エントリーする**（ピラミッディングはしない）
- 1つのトレンドイベントから複数回エントリーしうる（`entry_seq` = 1, 2, 3, ...）
- **エントリー回数の上限は設けない**（SYS-FX017 で上限設定を検証したが悪化したため不採用）

### 3-3. 追跡の終了条件（どれか1つで終了）

1. **ダウ理論の型崩れ**
   - UP: Higher Low を下抜け（Lower Low の形成）
   - DOWN: Lower High を上抜け（Higher High の形成）
2. **最大追跡時間 72時間**（`MAX_TREND_HOURS = 72`）を超過
3. **週内最終バー**に到達

### 3-4. 型崩れ後の追跡再開（H1継続確認）

M5で型崩れした後でも、**H1が型崩れ前の高値（UP）／安値（DOWN）を更新した場合は追跡を再開する**
（`confirm_mode = "new_extreme"`）。

> Train診断では、全トレード300件のうち **213件（71%）がこの再開由来**であり、
> 本戦略の主要な収益源になっている。

## 4. 出口（SYS-FX026 の変更点はここだけ）

### 4-1. 初期ストップ（1R の定義）

```
初期ストップ幅 = 0.703 × ATR(M5, 14)      ← これを 1R と定義する
```

- `stop_buffer_atr_m5 = 0.703` は、4通貨プールのM5バーレンジ/ATR比の **p25** から Train で導出
- ロング: `エントリー価格 − 1R`、ショート: `エントリー価格 + 1R`

### 4-2. 段階利確は**行わない**（トレール専業）

```
tp_levels = []        ← 空。分割利確は全廃（T-13）
```

> SYS-FX011 の旧設計（1R/2R/4R の3段階利確）は T-13 で廃止済み。
> 段階利確は勝ちトレードの伸びを削り、ペイオフレシオを悪化させていた。

### 4-3. 建値ストップ（ブレークイーブン）

**含み益が +1.0R に到達したら、ストップを建値へ移動する**（`breakeven_trigger_r = 1.0`）。

### 4-4. ATRトレーリングストップ ← **SYS-FX026 の変更点**

```
トレール幅 = 0.703 × 3.0 × ATR(M5, 14) = 2.109 × ATR(M5, 14)   ← 1R の 3.0倍
```

| | SYS-FX011（従来） | **SYS-FX026** |
|---|---|---|
| トレール幅 | 1R × **1.0** | 1R × **3.0** |

- 建値ストップ発動後、価格が有利方向に進むたびに、**最高値（UP）/最安値（DOWN）から
  トレール幅だけ離れた位置**へストップを引き上げる（引き下げはしない）
- **変更の根拠**: SYS-FX011 はトレールが狭すぎて勝ちトレードでもトレンドを追えておらず、
  ペイオフレシオが1.09（ほぼ1:1）に留まっていた。**K5m（コスト倍率）は
  「1トレードあたり粗利益 ÷ コスト」であり、1Rの定義をスケーリングしても分母分子が
  相殺して動かない。動かせる唯一の筋の良いレバーが「勝ちトレードがどこまで伸びるか」
  ＝トレール幅である**という理屈から、3.0倍のみを事前登録して検証した（OBS000013）

### 4-5. 決済理由の一覧（**ラベル名に注意**）

実装（`backtest_vol_breakout_dow_theory.py:235`）は決済ラベルを
`"SL_INITIAL_NO_TP" if n_levels_hit == 0 else "TP_THEN_SL_TRAIL"` で決めている。
**SYS-FX026 は段階利確を全廃（`tp_levels = []`）しているため `n_levels_hit` は常に 0 であり、
初期ストップ・建値ストップ・トレーリングストップの3つすべてが
`SL_INITIAL_NO_TP` という1つのラベルにまとめられる。**

| exit_reason | 実際に含まれるもの | スリッページ扱い | 3期間の実測 |
|---|---|---|---|
| `SL_INITIAL_NO_TP` | **初期ストップ + 建値ストップ + トレーリングストップ**（すべて） | 逆指値 1.0 pip | Train 345 / Val 88 / Test 114（**約97%**） |
| `WEEKEND_NO_TP` | 週末強制決済 | 成行 0.5 pip | Train 10 / Val 3 / Test 7 |
| `TP_THEN_SL_TRAIL` | （段階利確を使う設計でのみ発生） | 逆指値 1.0 pip | **3期間とも 0 件** |
| `MAX_HOLD` | 最大保有72時間超過 | 成行 0.5 pip | **3期間とも 0 件** |

> **重要**: `SL_INITIAL_NO_TP` の平均損益は Train +$9.97・Validation +$6.26・Test +$2.99 と
> **プラス**である。これは「損切りなのに儲かっている」のではなく、**上記のとおりこのラベルが
> 勝ちトレード（トレーリングストップ決済）も含んでいる**ためである。ラベル名は
> SYS-FX011 の段階利確設計時代の名残であり、誤読しやすいので注意すること。
>
> **コストモデル上は正しく扱われている**（`SL_INITIAL_NO_TP` は逆指値扱いで
> 保守的な 1.0 pip スリッページが課される）。
>
> **`MAX_HOLD` が0件** ＝ 72時間の保有上限は3期間を通じて一度も拘束していない
> （ダウ理論の型崩れか週末決済が必ず先に来る）。

### 4-6. 決済判定の粒度

**M5バー単位で判定する**（`m5_exit = True`）。

> 旧仕様はH1バー単位で判定しており、エントリー直後〜そのH1バー終了までの平均約30分が
> 「見えない窓」になっていた（外部レビュー §1-2、T-03で修正）。
> PJ000004 Q11（執行判定タイムフレームの粒度）の恒久ルールに準拠。

**同一M5バー内で利確条件と損切り条件が両方成立する場合は、損切りを優先する**（保守側）。

## 5. ポジションサイジング

### 5-1. リスク率 ← **SYS-FX026 の変更点**

```
1トレードのリスク額 = その時点の口座残高 × 0.65%     ← 複利
数量 = リスク額 ÷ 初期ストップ幅（1R）
```

| | SYS-FX011（従来） | **SYS-FX026** |
|---|---|---|
| `risk_pct` | 1.00% | **0.65%** |

**0.65% の導出（`amendment-01` §3、スイープではなく機械的に1点を決めた）**:

```
risk_pct = 1.00% × (目標DD 8.0% ÷ Train実測DD 12.08%) = 0.6623%
         → 0.05%刻みで切り捨て（保守側） → 0.65%
```

目標DD 8.0% は、K2m の基準10%に対し**20%の安全マージン**を取った値。

> **重要な但し書き（`amendment-01` §2 で結果を見る前に宣言済み）**:
> **サイジングの変更は「戦略の質の改善」ではなく「単位の変更」である。**
> 正の期待値を持つ戦略はサイジングを絞れば K2m（絶対DD閾値）を必ず通せるため、
> **K2m の充足は突破ではなく設定**である。サイジングで動かせない指標は
> **K5m・実効n・permutation p の3つだけ**。

### 5-2. レバレッジ上限

実質レバレッジが **25倍**（GMOコイン外国為替FXの規制上限）を超える場合、
そのトレードのリスク率を `25 ÷ leverage_ratio` に縮小する。

### 5-3. 破産ガード

残高が 0 以下になった時点で以後のトレードを行わない（3期間とも発動0件）。

## 9. 既知の弱点（採用判断の前に必ず読むこと）

1. **K5m（コスト倍率）が Test で基準未達**（3.95 / 5.49 / **2.56** vs 基準3.0）。
   本戦略が壊すために作った当の指標が、ホールドアウトで基準を割った
2. **実効n が Validation・Test とも未達**（355 / 91 / 121）。
   期間考慮後の閾値（PJ000004 Q15）でも 141 / 149 に届かず未達のまま
3. **通貨別の成績は期間ごとに入れ替わる**（Validation では GBP/JPY が負・Test では EUR/JPY が負、
   AUD/JPY は Train でほぼゼロだが Validation で突出）。各通貨 n=18〜47 では構造を読み取れない
4. **Test は基盤設計に対しては清潔なホールドアウトではない**。SYS-FX011 の改善ループで
   T-05 凍結前に14回以上参照されている。清潔なのはトレール幅・サイジングの変更部分のみ
5. **C品質チームの独立査読を経ていない**（司令塔判断で Test を優先したため）
6. **フォワードで実効n 300 に到達するには約21ヶ月かかる**見込み
