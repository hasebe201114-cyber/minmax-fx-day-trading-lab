## 1. 修正内容

### 1-1. 何が壊れていたか

`derive_vol_breakout_entry_params.to_h1()` は `resample("1h")` を **label 既定（=left）** で使うため、
`h1.index[i]` は**バーの「始値時刻」**である。一方 `simulate_dow_theory_trend()` は

```python
break_time = h1.index[break_idx]                    # = バー始値時刻
start_time = break_time + pd.Timedelta(minutes=30)  # = バー確定の30分「前」
```

としており、**エントリー探索がブレイクH1バーの確定30分前から始まっていた**。
ブレイク判定 `(高値−安値)/ATR ≥ 3.5`・方向判定 `終値>始値`・初期基準値 `break_bar["high"/"low"]`
はいずれも**バー確定後にしか分からない**ため、これは**先読み**である。

`00-spec.md` は一貫して「ブレイクバー**確定後**30分」と記載しており、**実装だけが仕様と食い違っていた。**

### 1-2. 修正

`simulate_dow_theory_trend()` に `bar_close_anchored: bool = False` を新設した。
`True` のとき、窓の起点を**バー確定時刻**（＝始値時刻 + 1バー分、`h1.index` の中央値差分から算出）
に置く。`start_time` と `end_time`（安全上限72時間）の**両方**を確定時刻からアンカーする
（spec の「ブレイク確定後72時間」に合わせる）。

**既定は `False`（旧挙動）に据え置いた。** 理由は、稼働中の SYS-FX012 フォワードテストを含む
既存戦略の結果を無断で変えないため。**SYS-FX026 は `BAR_CLOSE_ANCHORED = True` で再評価する。**

> **既定を反転するか（＝SYS-FX011/012 なども修正版で再評価するか）は `OBS000009` として
> 司令塔判断を仰ぐ。** `research/ACTIVE.md` の「🚨 未解決ブロッカー」に掲載した。

### 1-3. 再発防止（PJ000004 Q16 として恒久ルール化）

本件は既存の防御を3つすり抜けた。特に **T-17 の spec整合テストが
`assert WINDOW_START_MIN == 30` と「値」だけを見ており、「何から30分か」という基準点を
見ていなかった**ため、バグが存在したまま pass し続けた。

そこで **`tests/test_lookahead_entry_window.py` を新設**し、
**定数ではなく合成データで実際に生成されたトレードの時刻**を検証する形にした（4件pass）。

| テスト | 何を保証するか |
|---|---|
| `test_h1_index_is_bar_open_time_not_close` | 前提（`to_h1()` のインデックスは始値時刻）が変わったら落ちる |
| `test_entries_never_precede_break_bar_close_when_anchored` | **修正版では全エントリーがバー確定後**であることを実時刻で検証 |
| `test_legacy_mode_reproduces_the_known_lookahead` | 既定がまだ旧挙動であることを可視化（既定反転時に必ず落ちる） |
| `test_anchored_mode_shifts_window_by_exactly_one_bar` | 修正が窓を1バー後退させるだけであることを確認 |

## 3. 判定

**Test 判定 C（再現しなかった）。** amendment-02 §4 の事前登録に従い、
**採用を具申せず、司令塔へ REJECT を含む選択肢を提示する。**

**フォワードテストは投入しない**（`amendment-03` の投入判断は Test 判定 B を前提としていたため無効。
ワークフローの SYS-FX026 ステップは `if: false` のまま維持する）。

### 何が残り、何が消えたか（正直な整理）

**消えたもの**
- 「本PJ初の Train 必須ゲート全達成（9/9）」→ **Train の K2m が 10.75% で未達**、撤回
- 「Test でも部分的に再現（B）」→ **C（再現しなかった）**
- 「トレール幅3.0倍という単一レバーで K5m の壁を越えた」→ **Test では越えていない（1.686）**

**残るもの**
- **K4m（ペイオフ）は修正後も3期間すべて基準クリア**（2.345 / 2.815 / 1.642）。
  SYS-FX011 が一度も越えられなかった壁であり、これは先読みに依存していない
- **Train・Validation の permutation は修正後も有意**（0.005 / 0.032）
- **3期間とも純損益はプラス**（+$3,179 / +$616 / +$192）
- トレール幅拡大がペイオフを改善するという**メカニズム自体は否定されていない**

**要するに**: 「出口を広く取るとペイオフは確かに改善する」は本物だが、
**それはホールドアウトで K5m とコストの壁を越えるには足りなかった。**
本PJが EXP-FX000020 で到達した「現行のコスト構造では原理的に採用ゲートに届かない」
という結論（`PJ000004` Q14）を、SYS-FX026 は覆せなかった。

## 4. 司令塔への確認事項

1. **SYS-FX026 を REJECT 確定としてよいか。**（S戦略チームの見解: 事前登録した判定ルールに
   従えば C であり、REJECT が筋。ただし判定権限は司令塔にある）
2. **`OBS000009` 不具合1 の既定を反転するか。** 反転すると **SYS-FX011 / SYS-FX012 も
   同じ先読みを含んでいる**ことになり、**稼働中の SYS-FX012 フォワードテスト（2026-08-22開始）の
   前提も変わる**。選択肢:
   - (a) 既定を反転し、SYS-FX011/012 を修正版で再評価する（フォワードは仕切り直し）
   - (b) 既定は据え置き、SYS-FX012 のフォワードは「先読みを含む設計」と明記して継続する
   - (c) SYS-FX012 のフォワードは停止し、扱いを別途決める

   **S戦略チームの推奨は (a)。** SYS-FX012 のフォワードは実運用移行を目的としており、
   実行不可能なエントリーを含んだまま積み上げても移行判断に使えないため。
