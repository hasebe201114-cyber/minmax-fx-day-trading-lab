## 1. なぜフォワードテストなのか（目的の限定）

3期間（Train/Validation/Test）を終えて残った未達は次の2つだけである。

| 未達項目 | 性質 |
|---|---|
| **K5m コスト倍率**（3.95 / 5.49 / **2.56**） | 期間による振れが大きく、基準3.0が振れ幅のほぼ中央にある |
| **実効n**（355 / **91** / **121**） | 8ヶ月級の窓では構造的に到達不能 |

**どちらも「新しいパラメータ」では解決しない。必要なのは新しいデータである。**
フォワードテストの目的を次の1点に限定する:

> **ゲートを一切緩めずに、本物の未見データで実効nを積み増し、K5m が基準線 3.0 の
> どちら側に落ち着くのかを判定する。**

**採用GOの具申は行わない**（amendment-02 §10 のとおり）。本フェーズはペーパートレード
であり、実発注は一切行わない。

|---|---|
| 30日 | 2026-09-14 |
| 60日 | 2026-10-14 |
| 90日 | 2026-11-13 |

各チェックポイントで記録する（**閾値は一切変更しない**）:

3. 通貨別内訳・1通貨除外感度（amendment-02 §9 と同一手順）

## 4. 実効n についての現実的な見積り（**結果を見る前の正直な記録**）

Test の実績は **121トレード / 約8.5ヶ月 ≒ 月14トレード**。この頻度が続くと仮定すると:

| 経過 | 累積トレード数（見込み） |
|---|---|
| 30日 | 約14 |
| 90日 | 約42 |
| 1年 | 約170 |
| **実効n 300 到達** | **約21ヶ月後（2028年半ば）** |

**つまり、min_n_trades=300 をフォワードだけで満たすには約2年かかる。**
これは本フェーズ開始時点で分かっていることであり、90日チェックポイントで
実効nが未達であることを「悪い知らせ」として扱ってはならない。

**したがって 90日時点での判定は「n が足りたか」ではなく、次節の A/B/C とする。**

## 5. 90日チェックポイントの判定ルール（**データを見る前に固定**）

主判定は amendment-02 §4 と同じ4条件（①平均r_net > 0 ②K4mペイオフ ≥1.5
③K5m ≥3.0 ④permutation p <0.05）を用いる。ただし90日程度では permutation の
検出力が乏しいため、**④は参考扱いとし、主判定は①②③の3条件**とする。

| 分類 | 条件 | アクション |
|---|---|---|
| **A: 継続（有望）** | ①②③をすべて満たす | フォワードを継続し、実効nの蓄積を待つ。**この時点でも採用GOは具申しない** |
| **B: 継続（判断保留）** | ①を満たすが②③のいずれかが未達 | フォワードを継続。**K5m が 3.0 のどちら側に落ち着くかはまだ決まっていない**と記録する |
| **C: 中止を具申** | **①平均r_net が負** | 3期間すべてで正だった期待値がフォワードで負に転じた場合、レジーム変化または過学習の疑いが強い。フォワード中止と SYS-FX026 の REJECT を司令塔に具申する |

**早期中止条件（30日・60日でも適用）**: 累積の平均r_netが負、かつ決済済みトレードが
**20件以上**ある場合は、90日を待たずに C として司令塔へ報告する。
（20件未満での符号は偶然の範囲であり、早すぎる判断を避けるための下限）

## 7. 想定される失敗モード（データを見る前の正直な記録）

1. **90日では何も結論が出ない可能性が高い。** 決済済み約42件では K5m の推定誤差が
   大きく、3.0 のどちら側かを断定できない見込み
2. **フォワード期間のレジームが Train/Validation/Test と異なれば成績は変わる。**
   これは露呈することが望ましい
3. **フォワード基盤自体の不具合リスク。** SYS-FX012 では「Routineは成功と記録されるのに
   実データが更新されない」（2026-08-22）「cutoff以降が直近2日のローリング窓でしか
   見えていない」（OBS000009 不具合2）という2件の不具合が実際に発生している。
   **データ被覆診断（`data_coverage`）を毎回確認し、ギャップがあれば結果より先に報告する**
4. **本PJのスコープでは、フォワードだけで実効n 300 に到達する前に判断を迫られる可能性が高い。**
   その場合の扱い（n未達のまま採用可否を判断するのか）は司令塔判断事項として残る
