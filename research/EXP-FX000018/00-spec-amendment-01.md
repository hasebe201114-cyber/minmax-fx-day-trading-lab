## 1. 経緯 — 司令塔判断（2026-08-28）

`00-spec.md` §14 の Train 未通過（必須KPI 4/11）に対し、分解診断で主因を **本PJ必須の週末フラット制約**（毎週金曜にグリッドの損失側だけを強制実現させられる構造）と特定し、S戦略チームから次の具申を行った:

> (a) 週末持ち越し禁止の緩和可否のみ司令塔に確認 → (b) 不可ならレンジ相場フィルターを改善ループ第1試行として1回だけ試す → (c) それでも改善しなければ REJECT確定

これに対する司令塔の判断:

> **「1. 緩和しても良い。リスク対策は必要。」**

したがって **(a) を採用し、週末持ち越しを許可した上でリスク対策を設計に組み込む** 形で改善ループ第1試行を実施する。

### 1.1 スコープ変更の適用範囲（A設計チームの判断、明記）

週末持ち越し禁止は `CLAUDE.md`・`STRATEGY-BRIEF.md` §1.2・`SYSTEMS.md` P2・`PJ000004` Q7 に記載されたPJ全体の制約である。ただし本判断は SYS-FX024（両建て・グリッド系）の構造的行き詰まりに対する回答として出されたものであり、**フォワードテスト実行中の SYS-FX012 など既存戦略の前提を遡って変えるべきではない**。

したがって:

- **緩和は SYS-FX024（本EXP）に限定して適用する。** 他のSYSは従来どおり週末フラットを維持する
- PJ全体のルールとしては「**週末持ち越しは原則禁止。戦略の構造上どうしても必要な場合に限り、司令塔の明示判断のもとで、リスク対策（本amendment §3）を必須条件として個別に許可する**」という形に改める
- 他戦略への横展開が必要になった場合は、その時点で改めて司令塔判断を仰ぐ

## 3. リスク対策（新規、結果を見る前に固定）

司令塔の「リスク対策は必要」に対する具体設計。**W1・W4 はモデルの是正**（週末持ち越しを許可した瞬間に楽観バイアスが入るのを防ぐための実装要件）であり、**W2・W3 が新規のリスク制御**である。

### W1. 窓開け（ギャップ）約定モデル ★モデル是正・必須

現行エンジンは、逆指値がヒットしたバーで**必ずストップ価格ちょうどで約定**するモデルになっている。週内は M5 粒度なのでこの近似は妥当だが、**週末を跨ぐと金曜終値と月曜寄り値の間に窓が開き、ストップ価格では約定できない**。これを実装しないまま週末持ち越しを許可すると、損失が体系的に過小評価される（`PJ000004` Q11 と同種の楽観バイアス）。

事前登録する約定規則（買いポジションの場合。売りは対称）:

| 状況 | 約定価格 |
|---|---|
| 当バー始値 `open` ≤ ストップ価格 | **`open`**（窓開けで飛び越えたので寄り値で約定。逆指値スリッページ1.0pipは別途課す） |
| `open` > ストップ価格 かつ 当バー安値 ≤ ストップ価格 | ストップ価格（従来どおり） |
| 当バー始値 `open` ≥ 利確価格 | **`open`**（有利側の窓開け。指値は寄り値で約定するため利益側に働く） |
| `open` < 利確価格 かつ 当バー高値 ≥ 利確価格 | 利確価格（従来どおり） |

同一バーでストップ・利確の両方が窓開けで成立する場合は、親spec §3.4 と同じく**損切り優先**。

**この規則は週末フラット版（ベースライン）にも適用する。** 祝日等の小さな窓開けが同様に存在するため、比較の公平性を保つ必要がある。ベースラインの再計測はモデル是正であり、改善ループの試行にはカウントしない（`PJ000004` Q10 の「既知のバグ修正・検定手法自体の是正はカウントしない」に準拠）。

### W2. 週末ネットエクスポージャー上限 ★新規リスク制御

週内最終M5バー（従来の強制決済タイミング）で、**週末を跨いで持ち越すポジション量に上限を課す**。

導出（**損益非依存**、`scripts/derive_weekend_gap_risk_trainonly.py`、Train期間のみ）:

1. Train期間の各週について、「週内最終M5バーの終値 → 週明け最初のM5バーの始値」の**相対窓開け** `rel_gap = |open_mon − close_fri| / close_fri` を通貨別に集計する
2. 通貨別の **99パーセンタイル** `rel_gap_p99[pair]` を採る（p50/p95/max も記録）
3. 週末を跨ぐ想定損失を、**分散効果を一切認めない保守側**で見積もる:
   `est_gap_loss = Σ_pairs |net_notional_usd[pair]| × rel_gap_p99[pair]`
   - `net_notional_usd[pair]` は**買い想定元本 − 売り想定元本**（同一通貨の両建て分は窓開けに対して物理的に相殺するためネットで評価する）
   - 通貨間は**単純合算**（4通貨の日次リターン相関は0.68〜0.92と高く、分散効果を認めるのは楽観側になるため）
4. **`est_gap_loss ≤ WEEKEND_GAP_LOSS_BUDGET_PCT × equity_MTM` を満たすまで、含み損が大きいポジションから順に成行決済する**（outcome = `WEEKEND_TRIM`）
5. **`WEEKEND_GAP_LOSS_BUDGET_PCT = 10.0%`**（K2m の月間最大DD上限と同水準に揃える。事前登録した値であり、結果を見てから動かさない）

### W3. 最大保有期間 ★新規リスク制御

週末フラットが無くなると、含み損ポジションを無期限に抱え続けられてしまう（グリッド戦略が破綻する典型パターン）。

- **保有上限 = 48本（H4）= 8営業日**（再アンカー周期 R=24 の2倍）。超過したポジションは成行決済（outcome = `MAX_HOLD`）
- 根拠: 本PJのスコープ「ホールド期間 = 数日〜数週間」（`CLAUDE.md`・`STRATEGY-BRIEF.md` §1.2）の下限側に収まる保守的な設定。R の2倍という定義はパラメータ探索ではなく、既に凍結済みの R から機械的に決まる

### W4. 証拠金維持率によるロスカット ★モデル是正・必須

現行エンジンの破産ガードは `equity ≤ 0` のみで、実際のブローカーのロスカットより遥かに遅い。週末持ち越しを許可する以上、実運用と同じロスカットを入れないと生存バイアスが入る。

EXP-FX000005 T-12（`scripts/analyze_margin_call_stress.py`）で確認済みのGMOコイン外国為替FXのルールをそのまま使う:

- **証拠金維持率 = 有効証拠金（MTM equity）÷ 必要証拠金合計 × 100**
- **100%未満 → ロスカット（全ポジション強制決済）**（outcome = `LIQUIDATION`、成行スリッページ0.5pip）。以後そのエピソードでは新規建てを行わない
- **125%未満 → ロスカットアラート水準。新規エントリーを停止する**（既存ポジションは維持）
- 判定は**全M5バー**で行う（窓開け直後を取り逃がさないため）
- 必要証拠金は親spec §5 と同じ**合算方式**（保守側）

**この規則もベースライン（週末フラット版）に適用して再計測する**（W1と同じ理由）。

## 6. 想定される失敗モード（結果を見る前の正直な記録）

1. **週末持ち越しを許可しても改善しない可能性がある。** 親spec §14 の分解診断で、週末強制決済（−23,756 pips）と探索診断のMARK損（−26,004 pips）はほぼ同額だった。これは「**期限が来たときに含み損側だけが残っている**」というグリッドの構造そのものに由来し、期限が週末から MAX_HOLD（W3）に置き換わるだけで同じ損失が出るおそれがある。
2. **最大の損失源は損切り（−64,560 pips）であって強制決済（−23,756 pips）ではない。** 週末制約を外しても損切りは減らない。仮に週末損失が全額消えても、同一パラメータでの合計は −13,551 + 23,756 ≒ **+10,205 pips 相当までしか戻らない**（凍結パラメータでは −4,621 + 相当分）。DD・シャープ・PF の全ゲートを通すには足りない可能性が高い。
3. **W2・W3・W4 のリスク対策自体が新たな強制決済を生む。** リスク対策は必須だが、グリッドの収益構造とは逆方向に働く。
4. **MTM DD が悪化する。** 含み損を週末に抱えたままにできる＝MTMエクイティの谷が深くなる。K2m（月間10%・年間20%）は親specの Train でも既に未達（18.72%）であり、さらに悪化しうる。

これらは結果が悪かった場合の言い訳ではなく、**結果を見る前に予想として記録しておくもの**である。

### 解釈（正直な記録）

- **W-A は方向としては一貫して改善した**: 最終残高 −13.7%→−9.2%、月次シャープ −1.358→−0.751、PF 0.838→0.887、perm_p 0.7343→0.6723。週末強制決済（B-A で183件・平均−$0.42）が無くなった効果は実在する。
- **しかし §6 の失敗モード予想 #1 が的中した。** W-A では週末決済が消えた代わりに **MARK（再アンカー時の強制決済）が289件→377件（37.5%）に増加**し、平均−$0.72 の損失を出している。**「期限が来たときに含み損側だけが残っている」というグリッドの構造は、期限が週末から再アンカーに置き換わっただけで温存された。**
- **失敗モード #4（MTM DD の悪化）も的中**: B-A 16.93% → W-A 21.38%（K2m年間20%を超過）、W-B 34.33%。含み損を週末に抱えたままにできるということは、そのままエクイティの谷が深くなるということ。KPI達成数が 4/11→3/11 に落ちたのは、この年間DDゲートを落としたためである。
- **失敗モード #2 も的中**: 最大の損失源は依然として損切りであり（W-A: 160件・平均−$3.07 = 合計−$491）、週末制約とは無関係である。週末制約の緩和は、この主損失源に一切触れていない。
- **W-B（持ち越し方式との併用）は明確に悪化した**（−22.5%、DD 34.33%、MAX_HOLD 58件）。「持ち越せるようにすれば含み損が回復するのを待てる」という直観は支持されず、**待てるようにするほど損失が大きくなる**という結果になった。勝率は 64.7% と全候補中最高だが、ペイオフレシオが 0.425 まで悪化しており、典型的な「小さく勝って大きく負ける」形である。
