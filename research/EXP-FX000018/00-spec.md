## 2. フェーズゲート2: グリッドパラメータのデータ駆動導出（**損益非依存**、結果を見る前に固定）

prescreenの仮置き値（N=5・k=1.0・R=30）は「結果を見る前の当てずっぽう」であり、そのまま使うと事後正当化になる。以下の3つの導出アルゴリズムを**Train期間のデータのみ**に適用して確定する。**いずれも損益・勝率・PF等の成績指標を一切使わず、価格構造の統計量のみから決まる**（グリッド間隔を損益で最適化すると、それ自体がHARKingになるため）。

導出スクリプト: `scripts/derive_grid_params_trainonly.py`
出力: `research/EXP-FX000018/10-result/grid_params.json`

### D1. 再アンカー周期 R（H4バー本数）

1. 各通貨のTrain期間H4終値系列 `P_t` について、**分散比** `VR(h) = Var(P_{t+h} − P_t) / (h · Var(P_{t+1} − P_t))` を `h = 1..120` で算出する。
   - `VR(h) < 1` は平均回帰的（レンジ的）、`VR(h) > 1` はトレンド的を意味する標準的な統計量。
2. `h ∈ [6, 120]`（1日〜20営業日相当）の範囲で `VR(h)` を最小化する `h` を、その通貨の**最も平均回帰が強い horizon** とする。
3. 4通貨の値の**中央値**を取り、6の倍数（=1日）に丸める。
4. **週末フラット制約による上限**: 週末持ち越し禁止により1エピソードは最長でも1営業週（H4で30本）で強制終了するため、`R = min(R_derived, 30)` とする。下限は `6`。

### D2. グリッド間隔 k（×ATR(H4,14)）

1. 短期側の平均回帰 horizon `h*` を `h ∈ [1, 30]` の範囲で `VR(h)` を最小化する `h` として求める（通貨別 → 4通貨の中央値、丸めなし整数）。
2. Train期間の全H4バー `t`（ATRが有効なバーのみ）について `d_t = |P_{t+h*} − P_t| / ATR_t(14)` を計算し、**4通貨プールの中央値**を `k` とする（小数第2位で丸め）。
   - 根拠: グリッドの1刻み利確が到達可能であるためには、刻み幅が「平均回帰が最も効く horizon で典型的に到達する変位」と同スケールである必要がある。これは価格構造のスケールであって損益ではない。
3. **サニティ帯**: `k` が `[0.4, 2.5]` を外れた場合はその端点にクリップし、クリップした事実を`grid_params.json`と本specに明記する。

### D3. グリッド段数 N

1. Train期間の全H4バー `a` について、`R` バー先までの価格エンベロープを ATR 単位で計算する:
   `Env_a = max( (max High[a+1 .. a+R] − Close_a), (Close_a − min Low[a+1 .. a+R]) ) / ATR_a`
2. 4通貨プールの **80パーセンタイル** を `Env_80` とする。
   - 根拠（事前登録した設計思想）: 最外段のさらに1刻み外側に置くストップ `(N+1)·k` が、アンカー窓の価格エンベロープを**5回に4回は包含し、残り1回（トレンド発生時）は損失を打ち切る**ように設計する。80%という水準はリスク設計上の選択であり、損益を見て決めたものではない。
3. `N = round(Env_80 / k) − 1`、`[3, 12]` にクリップ。

### D4. 導出値の凍結

D1〜D3の出力は**Train期間のみ**から算出し、以後 Validation/Test を含む全評価で固定する。改善ループで再導出する場合は、その試行を1回分としてカウントし、変更点を本specに追記する。

## 3. 戦略ロジック（事前登録）

### 3.1 グリッドの生成（アンカー）

- アンカーバー `a`（H4）の**終値** `C_a` を中心、`step_a = k × ATR_a(H4,14)` を刻み幅とする。
- 買いレベル: `C_a − j·step_a`（j = 1..N）、売りレベル: `C_a + j·step_a`（j = 1..N）
- 買い側ストップ: `C_a − (N+1)·step_a`、売り側ストップ: `C_a + (N+1)·step_a`
- **先読み防止**: `C_a`・`ATR_a` はアンカーバーの確定後にのみ参照でき、生成したグリッドは**次のM5バーから有効**とする。
- 次のアンカーは `R` 本後のH4バー。ただし週内最終H4バーで全決済・グリッド破棄し、翌週の最初のH4バー確定後に新規アンカーを張る（週跨ぎのグリッドは持たない）。

### 3.2 エントリー・利確・損切り

- **エントリー（指値）**: M5安値が買いレベル `j` に触れ、かつそのレベルが未保有なら、そのレベル価格で1単位買う。売り側は対称。
- **利確（指値）**: 買いポジション `j` は、M5高値が `entry + step`（=そのポジションが生まれた世代の刻み幅）に触れたら決済。決済後、そのレベルは**再度エントリー可能な状態に戻る**（往復収益モデル）。売り側は対称。
- **損切り（逆指値）**: M5安値が買い側ストップに触れたら、その世代の買いポジションを全て成行決済し、**その世代のその側は次のアンカーまで新規停止**。売り側は対称。
- **週末強制決済（成行）**: 週内最終H4バーの終値で全ポジションを決済（outcome = `WEEKEND`）。

### 3.3 事前登録する2候補（**この1変数のみを動かす**）

| 候補 | 再アンカー時の既存ポジションの扱い |
|---|---|
| **G0（MARK方式）** | prescreenの探索診断と同一。再アンカー時点の終値で既存ポジションを**強制時価決済**（outcome = `MARK`）してからグリッドを張り直す |
| **G1（持ち越し方式）** | 再アンカー時に既存ポジションを決済しない。各ポジションは**生まれた世代の利確幅・ストップ価格を保持したまま追跡**し、新グリッドは新規エントリーのみを支配する。同一通貨・同一サイドの同時保有数は**合計N本**を上限とし、上限到達中は新規エントリーを見送る |

> **なぜ両方を走らせるか（正直な記録）**: prescreenで「MARKは平均−50.2 pipsでネットの足を引っ張っており、再アンカーという人為的な期限切れによるモデル上のアーティファクト」と記録済みである。ここでG1を「正しい設計」と決め打ちすると、探索診断の結果を見てから設計を選んだことになり HARKing に該当する。**両方を事前登録し、§7の選定ルールで機械的に決める。**

### 3.4 同一バー内の順序解決（prescreenの留保事項への対応）

探索診断はH4バーの高安のみで判定しており、同一バー内で利確と損切りが両方成立しうる場合の順序依存性が未対応だった。本specでは**執行判定をM5足で行う**ことでこの曖昧性を構造的に排除する。M5バー内でなお両方が成立しうる場合（1本のM5バーがストップと利確の両方を含む）は、**損切りを優先**する（保守側、事前登録）。

## 4. サイジング・損益・エクイティ（ダラーベース、事前登録）

### 4.1 グリッド1本あたりのロット

「1トレード＝残高の1%リスク」という既存の複利サイジング規約を、**グリッド1面（1通貨・1サイド・1世代）を1リスク単位**とみなす形に拡張する。

- アンカー時点の残高 `B`（USD、MTM equityではなく確定残高）に対し、**片側のグリッドが全段約定した状態で最外段ストップに到達した場合の損失が `RISK_PCT_PER_GRID = 1.0%` × B に一致する**ように、全段共通のロット `units` を決める。
- 買いレベル `j`（`C − j·step`）のストップまでの距離は `(N+1−j)·step`。全段合計の損失距離は `step · Σ_{j=1..N}(N+1−j) = step · N(N+1)/2`。
- したがって（JPYクオート通貨の場合）:
  `units = 0.01 · B · FX_{USDJPY} / ( step_JPY · N(N+1)/2 )`
- `units` はアンカー時に確定し、その世代のポジション全てに適用する（G1の持ち越しポジションは生まれた世代の`units`を保持）。
- **両建て時の最悪ケース**: 買い側・売り側が同一アンカー窓で両方とも全段約定→両方ストップという往復振れの場合、その通貨で最大 2.0% × B を失う。これは設計上許容し、実測値（両側同時ストップの発生件数）を結果に必ず記録する。

### 4.2 1ポジションのR定義（K5m・permutation testの単位）

- `initial_risk_j = (N+1−j)·step`（そのポジション固有のストップまでの距離、価格単位）
- `r_gross = 損益（価格単位、コスト前） / initial_risk_j`
- `cost_r = (2·spread + slippage_entry + slippage_exit)·pip / initial_risk_j`
- `commission_r = 0.00004 × (entry_price / initial_risk_j)`
- `r_net = r_gross − cost_r − commission_r`
- `dollar_pnl = r_net × initial_risk_j × units / FX_{USDJPY}` （＝USD建ての実損益。スワップは§4.5で別途加算）

### 4.3 エクイティカーブ（**時価評価**、本EXPの中核的な変更点）

既存パイプライン（`evaluate_period()`）は**確定損益のみ**でエクイティカーブを構成していた。シングルポジション・短期保有の戦略ではこれで実害が小さかったが、**両建てグリッドは含み損を抱えたままポジションを積み増す構造であり、確定損益ベースのDDは実態を大幅に過小評価する**。

事前登録:

- エクイティカーブは **`equity_t = 確定残高_t + 全オープンポジションの含み損益_t`（MTM）** とし、**全H4バー終値時点でサンプリング**する。
- K2m（最大DD）は Q9（PJ000004）に従い**ピーク比**（複利サイジングのため）で、この**MTMエクイティカーブ**上で計算する。
- 参考として確定損益のみのカーブ上のDDも並記するが、**判定にはMTMを使う**。
- 破産ガード: MTM equity ≤ 0 となった時点で以後の新規エントリーを停止し、`ruined = True` を記録する。

### 4.4 通貨換算

- 全損益・証拠金はUSD建てに換算する。JPY→USDの換算レートは、その時点のUSD/JPY M5終値を使う（DS-1のUSD/JPY系列。前方参照なし）。
- 4通貨すべてJPYクオートのため、非JPYペアの分岐は本EXPでは発生しない（将来EUR/USDを加える場合は要拡張）。

### 4.5 DS-7 スワップポイントの正味計上（prescreen残課題）

- ソース: `data/curated/ds-7.json`（`swap_long_jpy` / `swap_short_jpy`、**1,000通貨・1日あたりJPY**、日次時系列 v0.2）
- ロールオーバー時刻: **JST 06:00**（NY 17:00 相当。週末強制決済の境界と同一）。あるバーからバーへの遷移でJST 06:00 を跨いだ場合、その時点で保有中の全ポジションにスワップを付与する。
- 付与額（USD）: `swap_jpy_per_1000 × (units / 1000) × multiplier / FX_{USDJPY}`
  - 買いポジションは `swap_long_jpy`、売りポジションは `swap_short_jpy` を使う。**両建てでは両方が同時に発生し、自動的に正味で効く**（DS-7の理論値では long と short の和が常に負＝ブローカースプレッド分のコストになる）。
  - `multiplier`: 水曜→木曜のロールオーバーのみ **3**、それ以外は **1**（3日分付与の商慣行。DS-7 v0.2 は3倍付与を織り込んでいない素の日次理論値のため、ここで適用する）。
- スワップは `dollar_pnl` とは別に `swap_usd` として各ポジションに積算し、決済時に合算して**そのポジションの最終損益**とする（PF・ペイオフ・permutation testはスワップ込みの最終損益で計算）。
- **限界の明記**: DS-7 v0.2 は政策金利差ベースの理論値＋固定ブローカースプレッド（片道1円/日）の仮定であり、GMO公式スワップポイントの実測値ではない。本EXPが採用に進む場合、実運用移行前にGMO公式データでの再検証を必須とする（DATA-FX001の既存の留保をそのまま引き継ぐ）。

## 5. K7m（両建て証拠金消費率）の計算方法（事前登録）

### 5.1 定義

- 1ポジションの必要証拠金（USD）: `margin_usd = units × price_JPY / LEVERAGE(=25) / FX_{USDJPY}` （＝想定元本の4%）
- **通貨ペアごとの合算方式（本EXPの判定基準）**: 同一通貨ペアで買い・売りを同時保有している場合も、**両側の必要証拠金を単純合算する**。
- **参考として MAX 方式も併記**: 同一通貨ペアの両建て分は `max(買い側合計, 売り側合計)` のみを消費するとみなす（`simulator.margin_usage_pct()` の既存実装と同じ考え方）。
- ポートフォリオ全体の消費率: `K7m_t = Σ_pairs margin_usd_t / equity_MTM_t × 100`
- **分母は MTM equity（その時点の時価純資産）**。初期資金比ではない。理由: 証拠金維持率は実務上「そのときの純資産」に対して判定されるものであり、複利サイジング下で初期資金を分母に固定すると実態から乖離する（Q9と同じ論理）。
- **K7m = Train期間全体（全H4バー終値サンプル）における `K7m_t` の最大値**。閾値 **≤ 30%**。

> **なぜ合算方式を判定基準にするか（正直な記録）**: GMO外国為替FXの両建て時の証拠金計算規則（MAX方式か合算方式か）は DS-6（API仕様）で確認できていない。多くの国内FX業者はMAX方式を採る一方、両建て規制の変更で合算方式に転じた例もある。**確認が取れていない以上、楽観側（MAX方式）をゲートに使うべきではない**。DS-6でMAX方式が確認できた時点で amendment としてゲートを緩めることは許容する（その逆＝結果を見てから緩めることは禁止）。

### 5.2 証拠金ガード（戦略設計に組み込む）

- 新規エントリー時、そのポジションを追加すると合算方式の `K7m_t` が **30%** を超える場合、**そのエントリーを見送る**（prescreenで設計に組み込むと宣言済み）。
- ガードは**新規建ての瞬間にのみ**作用し、建玉を強制的に減らす設計ではない。したがって建てた後にMTM equityが目減りすれば観測K7mが閾値をわずかに上回りうる（`tests/test_grid_portfolio_engine.py`で不変条件として明文化）。それでもK7mはガードによってほぼ閾値内に収まるため、K7mを「合格した」と報告するだけでは意味がない。**必ず以下を併記する**:
  - `guard_block_rate` = ガードで見送られた新規エントリー数 / 見送りが無ければ発生していた新規エントリー総数
  - `K7m_unguarded` = **ガードを無効にした反実仮想シミュレーション**での最大証拠金消費率（構造的に必要としている証拠金の実像）
- **事前登録した解釈ルール**: `guard_block_rate > 20%` の場合、「証拠金制約によって戦略が実質的に別物へ変形している」とみなし、そのままの採用判断はしない（自動REJECTではなく、ロット縮小＝`RISK_PCT_PER_GRID` の引き下げによる再評価を改善ループの1試行として行う）。

### 6.1 K4m をなぜ PF ≥ 1.5 に置き換えるか（**結果を見る前の宣言**）

グリッド戦略は**構造上**、勝ちが「1刻み（+1×step）」・負けが「最外段ストップまで（最大 N×step）」という非対称な形をとる。R単位で見れば利確は `1/(N+1−j)` R（最内段では 1/N R）にしかならず、損切りは常に −1R である。したがって**ペイオフレシオが1.5を超えることは設計上あり得ない**。この事実はいかなる結果も見ずに、設計だけから確定的に言える。

K4mの本来の目的は「小さな利益を拾って大きな損失で吹き飛ぶ形（pennies in front of a steamroller）を排除する」ことにある。勝率が50%前後の戦略ではこの目的が「ペイオフ ≥ 1.5」と一致するが（勝率50%ならペイオフ1.5 ⟺ PF 1.5）、勝率が構造的に高い戦略ではペイオフレシオではなく**PF がその目的の正しい一般化**になる。そこで:

- **K4m'（必須）: Profit Factor ≥ 1.5**（勝率50%におけるK4mと厳密に等価な水準）
- ペイオフレシオの実測値も必ず記録するが、単独ではGO/REJECTを左右しない（参考2）

これにより実効的なPFゲートは1.5となり、K1m-b（PF≥1.2）は自動的に包含される（#2は#6に包含されるため、達成数のカウント上は両方を1票ずつ数えるが、実質的な拘束は#6）。**この置換は結果を見る前に本specで宣言したものであり、Train結果が出てから閾値を動かすことは禁止する。**

### 6.2 permutation test のクラスタ設計（**本EXP固有の保守化**）

プロジェクトの直近規約は「日ブロック」（`permutation_test_block()`、クラスタキー=エントリー日）だが、グリッド戦略では**同一アンカーエピソード内の全ポジションが1本の価格パスを共有する**ため、日ブロックでも依存構造を取り逃す。さらに週末フラット制約により、**1営業週が自然な独立ブロック**になる。

- **判定に用いる主検定（事前登録）: クラスタキー = エントリー時点のISO年-週（全通貨共通）**。Train 17ヶ月で約74クラスタ。同一週内の全通貨・全ポジションが同じ符号を引くため、通貨間相関とエピソード内依存の両方を同時に吸収する。
- 参考: 日ブロック（プロジェクト従来規約）も併記する。
- `n_eff` は `apply_correlation_discount=False`（相関ハンデの二重計上を避けるT-07規約に準拠）。加えて #8b として独立エピソード数（通貨×アンカー世代の総数）を別途ゲートする。

## 8. AUD/JPY 除外の可否（prescreen残課題への回答、事前登録）

探索診断でAUD/JPYが他3通貨より明確に弱かった（+1,540 pips vs +6,214〜+8,375 pips）が、**その結果を見てから通貨を落とすのは典型的なcherry-picking**であり、SYS-FX016（EXP-FX000010）で「通貨構成の操作は質の希薄化と選択バイアスを招く」という教訓を既に得ている。

事前登録:

- **ベースライン（§7の判定）ではAUD/JPYを除外しない。4通貨で判定する。**
- 除外を検討してよいのは、**損益に依存しない構造的な基準**に該当する場合のみとする:
  - `cost_ratio_pair = (2·spread + 1.0) / (k × median ATR_H4[pips])` を4通貨それぞれで算出し、
  - **ある通貨の `cost_ratio_pair` が4通貨の中央値の2倍を超える**場合、その通貨は「グリッド間隔に対してコストが構造的に重い」とみなし、除外候補とする。
  - この判定は§2の導出と同時に（Train損益を一切見ずに）行い、`grid_params.json` に記録する。
- 上記の構造的基準に該当しない場合、通貨除外は**改善ループの1試行**としてのみ許容し、その際も「除外の根拠は損益であり、選択バイアスのリスクがある」ことを結果に明記する。

## 12. 想定される失敗モード（結果を見る前の正直な記録）

1. **MTMエクイティでのDDが致命的になる**: 含み損を抱えたまま積み増す構造のため、K2m（月間10%・年間20%）が最も落ちやすいゲートだと事前に予想する。prescreenのpipベース合計が良好だったのは、含み損の途中経過を一切見ていないことによる可能性が高い。
2. **証拠金ガードが頻繁に発動する**: 4通貨×2サイド×N段を同時に持つと想定元本が膨らむ。`guard_block_rate` が大きければ、実質的にはグリッドが最後まで機能していないことになる。
3. **permutation（週ブロック）で有意にならない**: n=2,500超でもエピソード数は数百に留まり、独立情報量は見かけより遥かに少ない。
4. **週末フラット制約がグリッドの前提を壊す**: 毎週金曜に強制決済するため、含み損ポジションが「回復する前に切られる」構造になっている。MARK方式の−50.2 pipsと同じアーティファクトが、週次で必ず発生する。G1（持ち越し）でもこれは回避できない。

これらは結果が悪かった場合の言い訳ではなく、**結果を見る前に予想として記録しておくもの**である。

### 乖離要因の分解診断（`scripts/analyze_sysfx024_param_decomposition.py`）

| MARK | n=518（20.0%）・平均−50.2 pips・計 **−26,004** | **n=0** |
| WEEKEND | — | n=413（17.5%）・平均−57.5 pips・計 **−23,756** |

**1トレードあたりの平均値はほぼ一致している（TP +49.5 vs +50.1、STOP −149.1 vs −143.8）一方、件数構成が大きく違う。** 実装の整合性は取れており、差は執行モデルに帰着する:

1. **損切り件数が10.3% → 19.1% へ68%増（約−24,750 pips）。** 探索診断はH4足の高安のみで判定していたため、**1本のH4バーがグリッド段を貫いてストップまで到達したケースで「約定も損切りも一切記録しない」**という構造になっていた（未保有のまま `buy_disabled` が立つだけ）。M5足で順序解決した正式エンジンでは、**STOPの21.2%（95/449）が同一H4バー内での建て→切り**であり、探索診断がこれを丸ごと取りこぼしていたことが確認できる。これは楽観側に効く重大な差であり、prescreenの留保「同一H4バー内の高安到達順序を考慮していない」が想定以上に効いていた。
2. **MARK（−26,004 pips）が WEEKEND（−23,756 pips）にほぼ同額で置き換わった。** prescreenは「MARKは再アンカーという人為的な期限切れによるアーティファクトなので、持ち越し方式にすれば消える」と想定していたが、**本PJ必須の週末強制決済（土曜06:00 JSTまでに全決済）が、同じ性質・同程度の規模の強制決済損を毎週必ず発生させる**。さらに R=30 では週末フラットが再アンカーより先に来るため再アンカー自体が一度も発火せず（世代数 296 = 74週 × 4通貨）、**このパラメータでは G0 と G1 が完全に同一結果になる**。
3. 凍結パラメータ（R=24）では再アンカーが発火し G0/G1 が分岐するが、**持ち越し方式 G1 の方が悪い**（−20.2% vs −15.5%）。含み損ポジションを週末フラットまで長く抱えるため、WEEKEND決済の件数が183→359件へ倍増し損失が拡大した。

出力: `research/method-notes/sysfx024_param_decomposition.json`

### 解釈（正直な記録）

- **prescreenが最優先の検証事項として挙げた懸念がそのまま的中した。** 「pipベースの単純合計はSYS-FX023の教訓どおり正式パイプラインで再現しないことがある」という留保は正しく、しかも再現しなかっただけでなく**符号が反転**した。
- ただし今回の主因は prescreen が予想していた「ダラーベース複利サイジング・K7m」ではなかった。**K7mは20.1%で余裕を持って合格し、証拠金は一度も拘束していない。スワップの寄与も−$13で誤差範囲。** 実際の主因は **執行モデル（同一H4バー内の順序解決）と、本PJ必須の週末フラット制約**という、サイジングとは無関係の2点だった。
- §12「想定される失敗モード」で事前に挙げた4項目のうち、**#4（週末フラット制約がグリッドの前提を壊す）が的中**、#1（MTM DD）は部分的に的中（月間DD 18.7%で未達）、#2（証拠金ガード頻発）は**外れ**（発動率0%）。
- 統計的にも `perm_p(週ブロック) = 0.77`・平均が負であり、**「エッジが弱くてサンプル不足で検出できない」のではなく、明確に負の期待値を持つ**。SYS-FX023のような「実効n不足で判断できない」状態ではない。

### 次のアクション（司令塔判断待ち）

改善ループで動かせるレバーと、今回の分解診断から見た見込みを正直に整理する:

1. **グリッド間隔・段数の再導出（k を細かく、N を増やす）** — 分解診断は「パラメータではなく執行モデルが原因」と示しており、刻みを細かくすると同一H4バー内の建て→切りがむしろ増える方向に効く可能性が高い。**見込みは低い。**
2. **最外段ストップの撤廃または大幅な拡大** — STOPが最大の損失源（−64,560 pips）。ただしストップを外すと週末フラットで同じ損失がWEEKENDとして実現するだけであり、加えて無限ナンピンのリスク管理上の問題が生じる。**構造的に有望とは言えない。**
3. **レンジ相場フィルターの追加（トレンド局面ではグリッドを張らない）** — 損失の源はトレンド発生時の片側連鎖であり、理屈としては最も筋が良い。ただし「トレンドかレンジかを事前に判定する」ことは方向性予測に近く、**この projectがSYS-FX007〜023で20戦略にわたり失敗し続けてきたまさにその課題**に帰着する。本戦略の「方向性予測に依存しない」という設計思想とも矛盾する。
4. **週末フラット制約の緩和** — 最も効きうるが、これは**本PJのスコープ定義（CLAUDE.md・STRATEGY-BRIEF.md §1.2）の変更**であり、B/A/Sチームの裁量では動かせない。司令塔判断が必須。
5. **ここで打ち切り、REJECT確定とする** — 期待値が明確に負（perm_p 0.77）であり、SYS-FX023の「実効n不足で判断できない」状態とは異なり判断材料は十分揃っている。

**S戦略チームの具申: 4（週末制約の緩和可否）についてのみ司令塔判断を仰ぎ、それが「不可」であれば 3 を改善ループ第1試行として1回だけ試し、それでも改善しなければ 5（REJECT確定）とすることを推奨する。** 1・2は分解診断の結果から見込みが薄く、7回の枠を消化する価値が低い。
