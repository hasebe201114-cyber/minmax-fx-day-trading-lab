## 2. 保守的コストモデル（**拡張期間の損益を見る前に固定**）

司令塔の許可条件「保守的コスト仮定を条件に」に対応する。**当時のスプレッドを推測で決めるのではなく、実測して決める。**

### 2.1 導出方法（損益非依存）

Dukascopy は BID/ASK 双方のローソクを配信している。これを使い、**拡張期間の実際のスプレッドを測る**。

1. `BID_candles_hour_1.bi5` と `ASK_candles_hour_1.bi5` を、**拡張期間（2021-11〜2023-10）**と**GMO基準期間（2023-11〜2024-10）**の両方について取得する（H1・各24ヶ月 × 4通貨 = 192リクエスト、軽量）
2. 各H1バーで `spread_t = ask_close − bid_close` を pips 換算し、**通貨ごと・期間ごとの中央値**を取る
3. **era_ratio[pair] = median_spread(拡張期間) / median_spread(GMO基準期間)**
4. **保守的スプレッド**: `CONSERVATIVE_SPREAD[pair] = GMO_SPREAD[pair] × max(1.0, era_ratio[pair])`
   - **`max(1.0, ...)` により、実測が「当時の方が狭かった」と出ても現行値より安くはしない**（楽観側に倒さない）
5. スリッページ・手数料は現行の T-09 確定値をそのまま使う（成行0.5pip / 逆指値1.0pip / 手数料0.00004）

### 2.2 感度分析（必須）

上記 §2.1 の値に加え、**`×1.5` と `×2.0` の2水準でも同じ評価を実行し、3水準すべての結果を併記する**。いずれかの水準で結論が反転する場合、その事実を明記した上で**最も保守的な水準（×2.0）の結果を判定に用いる**。

## 5. 選定ルール（**結果を見る前に固定**）

拡張 Train での評価結果を、戦略ごとに次の3分類へ機械的に振り分ける。

1. **決着（有望）**: 拡張 Train で **実効n ≥ 300 を満たし、かつ必須ゲートを全て達成** → Validation を参照し、司令塔に採用可否を具申する
2. **決着（不採用）**: 拡張 Train で **実効n ≥ 300 を満たすが、必須ゲートに未達がある** → 「サンプルは足りたが基準に届かなかった」として **REJECT を確定**する（これが本EXPの最大の価値である。従来は「n不足で判断できない」で止まっていた）
3. **なお判定不能**: 拡張しても実効n < 300 → その戦略は本PJのスコープでは原理的に検証できないと記録し、司令塔判断を仰ぐ

**未達項目を見てから閾値・コスト仮定・対象戦略を変更しない。**

## 6. 想定される失敗モード（結果を見る前の正直な記録）

1. **拡張しても通らない可能性は十分にある。** その場合でも「サンプルを増やしても有意にならなかった」という、この projectがこれまで一度も得られなかった**明確な結論**が得られる。分類2は失敗ではなく成果である
2. **2021-11〜2023-10 は 2022年の円急落・BOJ介入を含む**。現行 Train（2023-11〜2025-03）と性質が大きく異なるため、レジーム依存の戦略は拡張期間で明確に悪化しうる。これは戦略の欠陥を暴くという意味で**望ましい**
3. **Dukascopy と GMO の系統差**が結果を汚染する可能性。§1.1 の接続部の価格連続性チェックと §2.2 の感度分析で監視する
4. **M5 バーが約2割少ない**ため、執行判定の機会がわずかに減り、損切りの検出が楽観側にぶれる可能性がある。この方向のバイアスは結果に必ず明記する
5. **SYS-FX025 の permutation 有意性は、週クラスタ数が約35→150 に増えても改善しない可能性**がある。その場合「独立情報量が4倍になっても有意にならない」という強い否定的証拠になる
