## 2. 保守的コストモデル（**拡張期間の損益を見る前に固定**）

司令塔の許可条件「保守的コスト仮定を条件に」に対応する。**当時のスプレッドを推測で決めるのではなく、実測して決める。**

### 2.1 導出方法（損益非依存）

Dukascopy は BID/ASK 双方のローソクを配信している。これを使い、**拡張期間の実際のスプレッドを測る**。

1. `BID_candles_hour_1.bi5` と `ASK_candles_hour_1.bi5` を、**拡張期間（2021-11〜2023-10）**と**GMO基準期間（2023-11〜2024-10）**の両方について取得する（H1・各24ヶ月 × 4通貨 = 192リクエスト、軽量）
2. 各H1バーで `spread_t = ask_close − bid_close` を pips 換算し、**通貨ごと・期間ごとの中央値**を取る
3. **era_ratio[pair] = median_spread(拡張期間) / median_spread(GMO基準期間)**
4. **保守的スプレッド**: `CONSERVATIVE_SPREAD[pair] = GMO_SPREAD[pair] × max(1.0, era_ratio[pair])`
   - **`max(1.0, ...)` により、実測が「当時の方が狭かった」と出ても現行値より安くはしない**（楽観側に倒さない）
5. スリッページ・手数料は現行の T-09 確定値をそのまま使う（成行0.5pip / 逆指値1.0pip / 手数料0.00004）

### 2.2 感度分析（必須）

上記 §2.1 の値に加え、**`×1.5` と `×2.0` の2水準でも同じ評価を実行し、3水準すべての結果を併記する**。いずれかの水準で結論が反転する場合、その事実を明記した上で**最も保守的な水準（×2.0）の結果を判定に用いる**。

## 5. 選定ルール（**結果を見る前に固定**）

拡張 Train での評価結果を、戦略ごとに次の3分類へ機械的に振り分ける。

1. **決着（有望）**: 拡張 Train で **実効n ≥ 300 を満たし、かつ必須ゲートを全て達成** → Validation を参照し、司令塔に採用可否を具申する
2. **決着（不採用）**: 拡張 Train で **実効n ≥ 300 を満たすが、必須ゲートに未達がある** → 「サンプルは足りたが基準に届かなかった」として **REJECT を確定**する（これが本EXPの最大の価値である。従来は「n不足で判断できない」で止まっていた）
3. **なお判定不能**: 拡張しても実効n < 300 → その戦略は本PJのスコープでは原理的に検証できないと記録し、司令塔判断を仰ぐ

**未達項目を見てから閾値・コスト仮定・対象戦略を変更しない。**

## 6. 想定される失敗モード（結果を見る前の正直な記録）

1. **拡張しても通らない可能性は十分にある。** その場合でも「サンプルを増やしても有意にならなかった」という、この projectがこれまで一度も得られなかった**明確な結論**が得られる。分類2は失敗ではなく成果である
2. **2021-11〜2023-10 は 2022年の円急落・BOJ介入を含む**。現行 Train（2023-11〜2025-03）と性質が大きく異なるため、レジーム依存の戦略は拡張期間で明確に悪化しうる。これは戦略の欠陥を暴くという意味で**望ましい**
3. **Dukascopy と GMO の系統差**が結果を汚染する可能性。§1.1 の接続部の価格連続性チェックと §2.2 の感度分析で監視する
4. **M5 バーが約2割少ない**ため、執行判定の機会がわずかに減り、損切りの検出が楽観側にぶれる可能性がある。この方向のバイアスは結果に必ず明記する
5. **SYS-FX025 の permutation 有意性は、週クラスタ数が約35→150 に増えても改善しない可能性**がある。その場合「独立情報量が4倍になっても有意にならない」という強い否定的証拠になる

### 8.1 実装上の重大な不具合と対策（2026-08-28、拡張期間の損益を見る前に発見・修正）

`fetch_dukascopy_m5.py` の初版に、**取得データが丸ごと1日ずれる**不具合があった。

- **原因**: Dukascopy のURLは `{YYYY}/{MM}/{DD}/` の形式だが、**月は0始まり（01月=00）である一方、日は1始まり**という非対称な仕様だった。実装では日も0始まりと誤解して `{DD-1}` を要求しており、全データが1日ずれていた
- **発見方法**: 取得データの曜日別分布に「**月曜が1日も存在しない**」という異常があり、DS-1(GMO) と重複する 2023-11 を取得して直接照合したところ、**そのままでは close 差の中央値 60.9 pips・相関 0.785、1日シフトすると 0.4 pips・相関 0.99989** と判明した
- **副作用**: 土曜を除外するロジックが、実際には**金曜の実データを除外**していた
- **なぜ危険だったか**: 1日ずれたデータも価格系列としては自然に見え、目視では気づけない。この状態で拡張 Train 評価を行えば、**シグナルと価格の対応が壊れた無意味な結果を「拡張の成果」として報告しかねなかった**

**対策（恒久）**: 取得の前に必ず `verify_against_ds1()` を実行し、**DS-1 と重複する月を取得して close 差の中央値と相関を検証、閾値（中央値 3.0pips 超 または 相関 0.99 未満）を外れたら取得自体を中断する**。修正後の検証結果は「共通6,288本・中央値差 0.400pips・相関 0.999905」で合格。

**誤ったデータで取得済みだった USD/JPY のファイルは破棄し、全通貨を取り直した。**

### 8.2 取得漏れ日の欠損と補填（2026-08-28、同じく損益を見る前に発見・修正）

日付ずれを直した後、**週末以外に最大9日連続の欠損**が残っていることが判明した。

- **原因**: `fetch_day()` はリトライ上限まで失敗すると None を返し、**その日を黙って捨てる**設計だった。公開フィードは 503 を返すことがあり、USD/JPY では 626 UTC平日のうち **46日（7.3%）** が欠落していた（例: 2023-03-18→03-27 で219時間、2022-06-20→06-27 で168時間）
- **なぜ危険だったか**: 欠損日があると、バックテストエンジンは隣接する2本のM5バーを連続とみなすため、**実際には9日離れた価格が「5分間の値動き」に見える**。ATR・ブレイク判定・ストップ到達のいずれもが壊れる
- **品質ゲート自身の欠陥**: 当初の `coverage_report()` は「1日あたりバー数の中央値」を見ていたため、**日がまるごと欠けているケースを検出できなかった**（存在する日はすべて288本なので「密度100%」と報告してしまう）。§1.1 Q1 の実装として不十分だった

**対策**: (a) `repair_dukascopy_m5.py` を新設し、対象期間のUTC平日のうちバーが1本も無い日を列挙して再取得・マージする。(b) `coverage_report()` に**欠損日数・週末を超える異常ギャップ・最大ギャップ時間**の検出を追加した。

補填後の USD/JPY: **149,890本 / 626日、欠損0日、異常ギャップ0件、最大ギャップ49.1時間（＝正常な週末）、接続部ギャップ −0.1pips**（補填前は265pips）。

- **41ヶ月・100万本のデータで、負相関は −0.22 前後で安定していた。** EXP-FX000019 の Validation（8ヶ月）で −0.058 まで弱まったのは、短期間ゆえの推定のブレだった可能性が高い
- **戦略Y は拡張期間で単独では明確に悪い**（Sharpe −0.77〜−0.98、DD 28〜30%）。**それでも合成すると DD が単独Xの 10.41% → 4.95% へ半減する**。単独では解決できなかった月間DDゲートを、合成が唯一クリアしている
- **合成は permutation の判定粒度で不利を負っている**: 単独戦略は日ブロックで評価され有意、合成は spec §3.2 で保守側の週ブロックを事前登録したため非有意（0.087〜0.157）。**同一粒度（日ブロック）で見れば合成も 0.022〜0.044 で有意**である。判定は事前登録どおり週ブロックのままとするが、**この非対称性は明記しておく**

### 10.5 正直な留保

- **リターンの絶対値は大きいが、額面通りには受け取れない。** SYS-FX011 は base で $1,000 → **$32,434（+3,143%、41ヶ月）**、×2.0 でも $12,241（+1,124%）。ただしこれは「増えた残高の1%を毎回リスクに晒す」複利サイジングの結果であり、**残高が30倍になってもスプレッド・スリッページが一定と仮定している**。K5m（コスト倍率）はまさにこの仮定の脆さに対する安全マージンを見る指標であり、**K5m が 2.2 しかないという事実は、コスト前提が少しでも悪化すれば結果が大きく変わることを意味する**。K5m 未達を「実際には儲かっているのだから些細だ」と扱うのは誤りである
- Dukascopy は GMO とは別ブローカーの気配値である。接続部の連続性（±1.1pips以内）と era_ratio の実測（1.00〜1.13）で妥当性は確認したが、系統差が完全に無いとは言えない
- **DS-7（スワップ）は 2023-11 以降しか存在せず、拡張期間ではスワップが計上されていない**。両建てグリッドの正味スワップは負なので、この欠落は合成側に有利（楽観側）に働く。実測寄与は17ヶ月・4通貨で −$13 と小さいが、拡張期間では未計上である

### 10.6 §5 の分類と結論

**全4戦略・全3コスト水準で「2_決着(不採用)」**（実効n ≥ 300 を満たしたが必須ゲートに未達）。

**これは従来の「不採用」とは質が違う。** これまでは「n不足で判断できない」まま止まっていた。今回は**十分なサンプルの下で、統計的に有意なエッジが存在することを確認した上で、必須ゲートに届かないと結論した**。spec §6-1 で「分類2は失敗ではなく成果である」と結果を見る前に宣言したとおりである。

### 10.7 司令塔への確認事項

拡張によって論点は次の2つに絞り込まれた。いずれも**私の裁量では決められない**。

1. **K5m（スプレッドコスト倍率 ≥ 3.0）をどう扱うか。** 全戦略・全水準で 1.52〜2.45 と未達で、**サンプルを増やしても構造的に改善しない**。この閾値を維持する限り、本PJの戦略群は原理的に採用に到達しない。一方でこの指標はコスト前提の脆さに対する安全マージンであり、安易に緩めるべきではない（§10.5）
2. **K4m（ペイオフレシオ ≥ 1.5）を、グリッドを含む合成に対して PF ≥ 1.5 へ置換してよいか**（EXP-FX000019 amendment-01 §7 で既に上程済み）。置換した場合、**SYS-FX025 base は必須ゲート 7/9**（残る未達は K5m と permutation週ブロックのみ）となる

### 10.8 司令塔回答と最終結論（2026-08-28）

**司令塔判断**: (1) **K5m は維持する**（緩和しない）。(2) **K4m→PF置換は承認**し、SYS-FX025 限定ではなく**グリッドを含む合成戦略全般の恒久ルール**として `PJ000004` Q14 に明記した。

**最終判定**: K5m を維持する以上、置換の適用有無に関わらず**判定に用いる保守的コスト水準（×2.0）ではSYS-FX025のPFも1.379と置換後の基準1.5に届かない**（§10.2 ×2.0行）。したがって**§10.6 の分類（全4戦略・全3コスト水準で「2_決着(不採用)」）は両論点の回答を経ても変わらず、そのまま確定する**。

- **SYS-FX011・SYS-FX012・SYS-FX018（単独）**: REJECT確定（K5m未達が恒久的な壁。単独では他にDD等の未達もあり）
- **SYS-FX025（SYS-FX011×SYS-FX024 R-Aの合成）**: REJECT確定。K4m→PF置換により「ペイオフ」ゲートは解消しうるが、**K5m（コスト倍率）とpermutation（週ブロック）の2点が残り、判定は変わらない**
- **本PJの現行戦略群は、現在のコスト構造（スプレッド・スリッページ・手数料前提）のままでは原理的に採用ゲートに到達できない**という構造的な結論が、5年拡張・ポートフォリオ合成という2方向の粘りの検証を経て確定した

**次のアクション（司令塔確認事項）**: 上記の結論を受け、本PJの方向性転換が必要。候補（司令塔判断待ち、次セッションで具申）:
1. コスト構造そのものの改善（1トレードあたりの想定Rを大きくする＝保有期間を伸ばす、執行頻度を下げてスプレッド影響を薄める等）でK5mの構造的改善を狙う新設計
2. 新カテゴリの戦略（本PJ未着手のニュース窓トレード等）の探索に着手
3. GMO以外のブローカー・口座条件（スプレッドがより有利な条件）の調査
4. なお `SYS-FX024`（EXP-FX000018）単独のREJECT具申は、本回答とは別に司令塔確認が未了のまま残っている（引き継ぎノート参照）。拡張Trainでの実測（Sharpe −0.769〜−0.975、DD 28〜30%、§10.4）はREJECT側をさらに補強する材料
