# データ取得仕様書 - DATA-FX001

> 担当: 設計チーム（strategy-architect）
> 起票: 2026-08-13
> 対象: SYS-FX007（レンジブレイク・プルバック戦略）の検証に必要なデータ層 DS-1〜DS-8
> バージョン: v2（2026-08-13 DS-8 追加: 注文板 / トレーダーセンチメント）

## 1. 概要

本 DATA チケットは、EXP-FX000001（SYS-FX007 レンジブレイク・プルバック戦略 v2）の検証に必要な 8 系統のデータ（DS-1〜DS-8）を取得・検証・カタログ化する。

## 2. データ系統（DS シリーズ）

### DS-1: OHLCV（必須・最大）

| 項目 | 値 |
|---|---|
| 通貨ペア | USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD（5 通貨） |
| 期間 | 2020-01-01 〜 2025-12-31（5 年） |
| 粒度 | **M5 を最優先**（最低 M15）。M1 は容量削減のため派生生成 |
| 列 | open, high, low, close, volume |
| 主ソース | dukascopy / histdata.com / GMO 公式 `/public/v1/klines` |
| 想定サイズ | 5 通貨 × 5 年 × M5 = 約 750 万行/通貨 × 5 列 |
| 取得優先度 | **1（最優先）** |
| 派生 | **S/R ラインの計算元**（OBS000001 v2） |

#### 取得スクリプト仕様
- 出力: `data/raw/ds-1/ohlcv_<pair>_<granularity>_<start>_<end>.csv`
- 検証: 連続性チェック、欠損率 < 0.1%、OHLC 整合

### DS-2: スプレッド時系列（必須）

| 項目 | 値 |
|---|---|
| 通貨ペア | 5 通貨全て |
| 期間 | 2025-01-01 〜 2025-12-31（6 ヶ月、ライブ検証用に最新） |
| 粒度 | 1 分粒度 |
| 列 | timestamp, pair, bid, ask, spread_pips |
| 主ソース | GMO 公式 `/public/v1/ticker` |
| 想定サイズ | 5 × 26 万行 = 約 130 万行 |
| 取得優先度 | **1（最優先）** |

### DS-3: 経済指標カレンダー（必須）

| 項目 | 値 |
|---|---|
| 内容 | 経済指標の発表日時、通貨、重要度、実績・予想・前回 |
| 期間 | 2020-01-01 〜 2025-12-31（5 年） |
| 主ソース | investing.com / ForexFactory / 各国中央銀行公式 |
| 想定サイズ | 約 600-1200 行 |
| 取得優先度 | 2 |

### DS-4: セッション境界 + ボラ/出来高集計（必須）

| 項目 | 値 |
|---|---|
| 内容 | 東京/ロンドン/NY セッションの境界時刻、各セッションの典型ボラと出来高 |
| 期間 | 2020-01-01 〜 2025-12-31（5 年） |
| 粒度 | 1 時間粒度 |
| 主ソース | **DS-1 から派生**（自前計算） |
| 想定サイズ | 約 220 万行 |
| 取得優先度 | 2 |

### DS-5: スリッページ代表性データ（必須）

| 項目 | 値 |
|---|---|
| 内容 | 成行注文の slippage 実測値 |
| 期間 | 2025 年 Q3-Q4 |
| 主ソース | **GMO テストネットがあれば優先**、なければ 0.5 pip 固定フォールバック |
| 想定サイズ | 1 行（固定フォールバック時）/ 100+ 注文（テストネット時） |
| 取得優先度 | 1 |

### DS-6: GMO コイン API 仕様（必須）

| 項目 | 値 |
|---|---|
| 内容 | API エンドポイント、rate limit、注文タイプ、取引単位、取扱ペア一覧、最小ロット、レバレッジ、**トレーダーセンチメント endpoint の有無** |
| 主ソース | `https://api.coin.z.com/docs/` |
| 想定サイズ | 構造化 JSON 1 ファイル |
| 取得優先度 | **1（最優先・他の DS 取得の前提）** |

#### DS-6 に追加で確認する項目（v2 拡張）
- `/public/v1/sentiment` または同等のトレーダーセンチメント endpoint
- 注文板（DOM）snapshot の提供有無
- GMO FX のリテール API で取得できる情報の限界

### DS-7: スワップポイント日次時系列（必須）

| 項目 | 値 |
|---|---|
| 通貨ペア | 5 通貨全て |
| 期間 | 2024-01-01 〜 2025-12-31（2 年） |
| 粒度 | 日次 |
| 列 | date, pair, swap_long, swap_short（pips） |
| 主ソース | GMO 公式のスワップポイントページ |
| 想定サイズ | 約 3650 行 |
| 取得優先度 | 2 |

### DS-8: 注文板 / トレーダーセンチメント（v2 新規・必須）

| 項目 | 値 |
|---|---|
| 内容 | 注文板（depth of market）またはトレーダーセンチメント（long% / short%） |
| 通貨ペア | 5 通貨全て |
| 期間 | 2024-06-01 〜 2025-12-31（最新 1.5 年、ライブ検証用に十分なサンプル） |
| 粒度 | 1 分粒度の snapshot |
| 列 | timestamp, pair, top_bid, top_ask, bid_size_top, ask_size_top, sentiment_long_pct, sentiment_short_pct |
| 主ソース | **GMO 公式 API で取得可能な範囲**を確認の上、以下を併用: (1) `/public/v1/ticker` の bid/ask/size（top-of-book）、(2) `/public/v1/sentiment` 等のセンチメント endpoint、(3) 取得不可なら MYFXBook / OANDA 等の公開センチメントを代用 |
| 想定サイズ | 5 × 26 万行 = 約 130 万行 |
| 取得優先度 | **1（最優先・v2 で追加）** |

#### 取得スクリプト仕様
- 出力: `data/raw/ds-8/orderbook_<pair>_<start>_<end>.csv`
- 検証: bid-ask 整合、sentiment の合計が 100±1% 以内
- **フォールバック**: GMO でセンチメントが取得できない場合、**MT-3 をスキップして MT-1 + MT-2 + 残り条件での評価に切り替え**（`--mode fallback`、OBS000001 C8 参照）

#### 想定される取得パターン
- **パターン A（最良）**: top-of-book bid/ask/size + sentiment_long% が取得できる
- **パターン B（次善）**: top-of-book のみ。sentiment は MYFXBook 等から別途取得
- **パターン C（フォールバック）**: top-of-book のみ。sentiment は取得せず、MT-3 をスキップ

## 3. 取得順序と依存関係

```
DS-6 (API 仕様) ─── 全 DS 取得の前提、DS-8 の取得可否も DS-6 で確認
        ↓
    DS-1 (OHLCV) ──┬─→ DS-4 (セッション境界、自前計算)
                   ├─→ DS-2 (スプレッド)
                   └─→ **S/R ライン（DS-1 から派生、MT-2 で使用）**
        ↓
    DS-3 (経済指標カレンダー)
        ↓
    DS-5 (スリッページ)
        ↓
    DS-7 (スワップポイント)
        ↓
    DS-8 (注文板 / センチメント) ※ DS-6 で取得可否確認後に着手
```

DS-6 と DS-1 を最優先で取得し、並列で DS-3、DS-5、DS-7 を進める。**DS-8 は DS-6 で取得可否を確認した上で着手**（パターン A/B/C を決定）。

## 4. 品質ゲート（Q1〜Q9 適用）

LP ラボ PJ000004 §3 と CLAUDE.md §「マルチタイムフレーム戦略ラボ固有の検証ステップ」を踏襲。

- **Q1**: データ欠損の網羅的検出
- **Q2**: ウォームアップ期間の前倒し
- **Q3**: 平滑化系列の併記
- **Q4**: implied コストの自動反映
- **Q5**: データソース/取得日の記録
- **Q6**: 通貨ペア単位の decimals 整合性
- **Q7**: 週末持ち越し禁止の保証
- **Q8**: 両建ての証拠金消費追跡
- **Q9**: スワップポイント両側反映
- **Q10**（v2 新規）: **注文板 / センチメントの連続性チェック**（top-of-book が連続的に取得できているか、sentiment の合計が 100±1% か）

## 5. ディレクトリ規約

- `data/raw/<ds-id>/<source>__<pair>__<granularity>__<start>__<end>.csv`（生データ）
- `data/curated/<ds-id>.json`（検証済み・正規化済み）
- `data/curated/ds-1-sr-lines.json`（v2 新規: DS-1 から派生した S/R ライン一覧）
- `data/MANIFEST.json`（全データ系列のメタ情報一覧、Q5 準拠）

## 6. 受入条件

- DS-1〜DS-8 全てが `data/curated/` に存在（DS-8 は取得パターン A/B/C のいずれかで成立）
- `data/curated/ds-1-sr-lines.json` に S/R ラインが記録されている
- `data/MANIFEST.json` に全データ系列の `source` / `fetchedAt` / `sha256` 記録
- Q1〜Q10 全て合格
- 検証スクリプト `scripts/data/verify-ds.ts` が全 DS を対象に 10 ゲートを実行し、`reports/ds-verification-YYYYMMDD.json` を出力
