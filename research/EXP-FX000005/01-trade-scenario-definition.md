## 1. 戦略の一言要約

H1足で「ボラティリティ・ブレイク」を検出し、その後のトレンド継続中はM5足のダウ理論スイング構造
（切り上げ安値/切り下げ高値）に基づいて**押し目買い・戻り売りを繰り返す**。1トレンドイベントにつき
1通貨1ポジションを維持し、型崩れ後もH1が継続を示せば追跡を再開する。

## 2. 対象範囲

| 項目 | 値 |
|---|---|
| 対象通貨 | USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY（4通貨。EUR/USDはTrain単独結果に基づき除外） |
| Train期間 | 2023-11-01 〜 2025-03-31 |
| Validation期間 | 2025-04-01 〜 2025-11-30 |
| Test期間 | 2025-12-01 〜 2026-08-15 |
| データ | GMO公開klines API由来のM5 OHLCV（`data/curated/ds-1.json`）。M5からH1へリサンプルして使用 |
| 保有制約 | 週末持ち越し不可（土曜06:00 JSTに強制決済） |

## 3. 検出層（H1）— トレンドイベントの起点

| パラメータ | 値 | 説明 |
|---|---|---|
| `N_BREAKOUT` | 3.5 | H1バーの「レンジ幅(高値-安値) ÷ ATR(H1,14,Wilder)」がこの値以上のバーを検出対象とする |
| 方向判定 | バー終値 > 始値 → UP、終値 < 始値 → DOWN | ブレイクバー自体の陽線/陰線で初期方向を決める |
| ATR | Wilder方式ATR(14) | H1・M5とも同一方式 |

この条件を満たすH1バーが確定した時点を「ブレイクバー確定」とし、以降のエントリー層の起点とする。
1本のブレイクバーが1件の「トレンドイベント」に対応する（同一通貨で複数のブレイクバーが時間的に近接して
発生した場合、複数のトレンドイベントが並行して追跡される — §8の既知の簡略化を参照）。

## 4. エントリー層（M5、ダウ理論連続追跡）

### 4.1 追跡開始

- ブレイクバー確定後 **30分**（準備期間）経過してから、M5足でのスイング追跡を開始する
- 追跡の起点（初回の「直前確定安値/高値」）は**ブレイクバー自身の安値（UP方向）/高値（DOWN方向）**

### 4.2 スイング構造の検出（ZigZag）

| パラメータ | 値 | 説明 |
|---|---|---|
| `ZIGZAG_THRESHOLD_ATR_M5` | 1.0 × ATR(M5,14,Wilder) | この閾値以上の逆行でスイング転換点（ピボット）を確定する。**暫定値**（Trainデータからの正式導出は未実施、§9参照） |

### 4.3 エントリー条件

- **UP方向（押し目買い）**: 新しく確定した安値ピボットが直前の確定安値より**高い**（Higher Low）場合、
  そのピボット確定バーの**終値**でエントリー
- **DOWN方向（戻り売り）**: 新しく確定した高値ピボットが直前の確定高値より**低い**（Lower High）場合、
  そのピボット確定バーの終値でエントリー
- エントリー注文種別: **成行**（0.5pipスリッページを想定、§6参照）
- 各エントリーはトレンドイベント内で何番目か（`entry_seq`、1始まり）を記録する。診断分析の結果、
  `entry_seq=1`（初回エントリー）はSL到達率42.8%と2回目以降（33〜39%）より明確に高いと判明したが、
  初回エントリーを除外する対策は連敗クラスタの改善にならず不採用（§9・§10参照）。現行は全エントリーを
  そのまま採用する。

### 4.4 トレンド終了（型崩れ）条件

- **UP方向**: 新しい安値ピボットが直前確定安値より**低い**（Lower Low）
- **DOWN方向**: 新しい高値ピボットが直前確定高値より**高い**（Higher High）

型崩れが確定すると、即座にトレンド終了とはせず「H1継続確認待ち」状態に入る（§4.6）。

### 4.5 1通貨1ポジション制約

新規エントリーは**直前ポジションの決済（exit_time）後にのみ**許可する。決済前に確定したHigher
Low/Lower Highピボットは機会として見送り、キューイングしない（決済後に新たに形成される押し目/戻りを待つ）。
ダウ理論のスイング構造追跡（型崩れ判定）自体はポジション保有状況に関わらず継続する。

### 4.6 M5型崩れ後のH1継続確認による再開

型崩れ（Lower Low/Higher High）が確定しても、以下の条件でM5追跡を再開する：

- **H1継続確認の定義**: 型崩れ以降のH1バーの高値（UP方向）/安値（DOWN方向）が、当該トレンド開始
  （ブレイクバー）から型崩れ確定時点までのH1高値/安値を更新したら継続確認とする
- 確認できたら追跡を再開し、基準安値/高値（直前確定安値/高値）は「確認待ち」の間にM5で記録した
  実際の最安値/最高値にリセットする
- 確認前に安全上限（§4.7）に到達するか週末クローズになった場合は、そのままトレンド終了とする
- 1通貨1ポジション制約（§4.5）は再開後も継続適用する
- 診断分析の結果、再開後のエントリーはSL到達率36.1%（非再開時42.6%）と明確に安全であることを確認済み
  （§9）。この再開メカニズム自体が質のフィルターとして機能している。

### 4.7 安全上限・停止条件

| 条件 | 値 |
|---|---|
| 追跡上限時間 | ブレイクバー確定後 **72時間**（H1継続確認による再開があっても延長されない） |
| 週末クローズ | 土曜 06:00 JST 以降は新規エントリー・追跡を行わない |
| 経済指標カレンダー・ブラックアウト（§4.8） | 対象窓内は新規エントリーのみ停止（構造追跡は継続） |

### 4.8 経済指標カレンダー・ブラックアウト窓

BOJ金融政策決定会合・FOMC会合（`scripts/economic_calendar.py`にWebSearchで検証済みの日程をハードコード）
の**[開催初日 − 24時間, 開催最終日 + 24時間]**を新規エントリー禁止窓とする。対象は4通貨すべて
（BOJは直接効果、FOMCは円・ドル全体への間接効果として全通貨に適用）。

- **明記すべき限界**: 事前に日程が公表されているBOJ/FOMC会合のみが対象。予定外の地政学ショック
  （例: 2025-06-13のイスラエルによるイラン攻撃）は原理的に防げない（§10 課題1）

## 5. イグジット層（H1バーで判定、ポジション単位）

### 5.1 ストップロス（初期）

| 方向 | 計算式 |
|---|---|
| UP | `stop0 = pivot_low − stop_buffer_atr_m5 × ATR(M5)` |
| DOWN | `stop0 = pivot_high + stop_buffer_atr_m5 × ATR(M5)` |

`stop_buffer_atr_m5 = 0.703`（4通貨プールのM5バーレンジ/ATR比のp25、Trainデータから導出済み）。

### 5.2 段階利確（テイクプロフィット）

| 段階 | 目標R | 決済比率 |
|---|---|---|
| TP1 | 1.0R | 40% |
| TP2 | 2.0R | 35% |
| **TP3** | **4.0R**（2026-08-20改訂、旧3.0R） | 25% |

TP1到達時点でストップを建値（エントリー価格）に移動する（ブレイクイーブン化）。

**TP3改訂の根拠**: TP_FULLトレードのMFE（最大順行幅）分析で3R到達後も価格が伸びる余地が確認され、
Train単独の反実仮想スイープでTP3=4RがmeanR+13.4%・PF+9.1%を示した（実効n-10.9%とのトレードオフ）。
Validation/Testでも3期間とも最大連続損失が旧設定と完全一致（6/6/5）することを確認した上で採用
（改善ループ第6試行、§9参照）。

### 5.3 トレーリングストップ

TP1到達（ブレイクイーブン化）以降、残存ポジションに対してH1バーごとにATRトレーリングを適用する：

- UP: `stop = max(stop, bar_open − atr_trail_multiplier × ATR(H1))`
- DOWN: `stop = min(stop, bar_open + atr_trail_multiplier × ATR(H1))`
- `atr_trail_multiplier = 3.23`（Train導出値、72時間MFE中央値ベース）
- ストップは常に有利な方向にのみ更新（タイト化のみ、緩めない）
- 建値へ移動するタイミングをTP1到達より早める案（`breakeven_trigger_r`をTP1未満に設定）はTrain単独の
  反実仮想スイープで検証し、早めるほどmean_Rが単調に悪化すると判明したため不採用（現行のTP1連動が
  最良、§9参照）。

### 5.4 決済理由（exit_reason）の分類

| 値 | 意味 |
|---|---|
| `SL_INITIAL_NO_TP` | TPに一度も到達せず初期/建値前ストップで決済 |
| `TP_THEN_SL_TRAIL` | 部分利確後、トレーリングストップで残数量を決済 |
| `TP_FULL` | 3段階すべてのTPに到達（全量利確） |
| `WEEKEND_NO_TP` | TP未到達のまま週末強制クローズ |
| `TP_THEN_WEEKEND` | 部分利確後、週末強制クローズ |
| `MAX_HOLD` | 最大保有バー数（240 H1バー=10日、暴走防止の安全上限）到達 |
| `NO_H1_DATA_AFTER_ENTRY` | エントリーが利用可能なH1データの最終バー付近で発生し、以降のバーが存在しない場合の即時フラット決済（r=0、2026-08-20修正で追加。§10課題7参照） |

### 5.5 決済注文種別（コストモデルとの対応）

| イグジット経路 | 注文種別 | スリッページ |
|---|---|---|
| TP到達分 | 指値 | 0 |
| SL・トレーリングストップ分 | 指値 | 0 |
| 週末強制クローズ・MAX_HOLD分 | 成行 | 0.5 pip |

決済が複数経路にまたがる場合（例: TP1到達後トレーリングで残り60%を決済）、到達したTP比率
（`fraction_via_tp`）で按分してコストをブレンドする。

## 9. エントリー/イグジット診断分析の要点（改善ループ第4〜6試行）

司令塔からの追加依頼を受け、以下4点を診断した（詳細は`00-spec.md`・`research/method-notes/entry_exit_diagnostics.json`参照）。

1. **継続/反転の事前判別**: 型崩れ追跡開始からの経過M5バー数のみ統計的に有意（継続群平均212.5バー
   vs 反転群172.1バー、perm_p=0.025）。単独で方向を確信を持って事前判別できる強いシグナルはない。
2. **SL到達の内訳**: `entry_seq=1`（トレンドイベント内の初回エントリー）のSL率42.8%が2回目以降
   （33〜39%）より明確に高い。初回エントリーを除外する対策を検証したが、連敗クラスタ（地政学ショック等
   による複数通貨同時損失）はentry_seq=1に限らず発生するため改善にならず、かつ総トレード数減少で
   残存クラスタが見かけ上さらに伸びる副作用があり不採用（Train最大連続損失6→10に悪化）。
3. **TP水準の引き上げ**: TP3を3R→4Rに引き上げる案を検証し採用（§5.2参照）。TP3=5R・6Rも試したが
   実効サンプル数のさらなる悪化に見合う追加の質的改善は乏しく、4Rを採用。
4. **建値トリガーの早期化**: TP1(1.0R)より早く建値へ移すか検証したが、早めるほどTrainのmean_Rが
   単調に悪化（1.0R:0.428→0.7R:0.406→0.5R:0.392→0.3R:0.378）し不採用。

また、エントリー機会拡大策（改善ループ第4試行: ブレイク検出閾値N・ZigZag閾値・カレンダー窓バッファの
緩和）も個別・組み合わせで検証したが、いずれも実効サンプル数を増やす代わりにトレード品質（最大連続損失・
ペイオフ比）を犠牲にするトレードオフを示し、不採用となっている。

## 10. 未確定・暫定パラメータ

- `ZIGZAG_THRESHOLD_ATR_M5 = 1.0` は改善ループ第1試行で設定した**暫定固定値**であり、
  Trainデータからのパーセンタイル等による正式導出は行っていない（§4.2）
- カレンダーブラックアウトのバッファ（24時間）は事前登録した固定値であり、Train最適化はしていない
  （改善ループ第4試行の感度分析でこの値を動かす検証は実施済み、いずれも改善せず不採用。`00-spec.md`参照）
- `TP3=4.0R`（§5.2）はTrain単独の反実仮想スイープで選定した値であり、パーセンタイル等による正式な
  数理的導出ではない（改善ループ第6試行、§9参照）。5R・6Rも試したがトレードオフ上4Rを採用した経緯を
  `00-spec.md`に記録済み。

## 11. 課題（未解決事項）

1. **予定外の地政学ショックに対する脆弱性**: 経済指標カレンダー・ブラックアウト窓（§4.8）は事前に
   日程が公表されるBOJ/FOMC会合のみを対象とし、2025-06-13のイスラエルによるイラン攻撃のような
   予定外イベントは防げない。Validationの最大連続損失(6)の主因であり、KPI改善が進まない最大の要因。
2. **実効サンプル数が全期間で閾値未達**: `min_n_trades_effective`(≥300)に対し、
   Train100.7・Validation30.4・Test50.5（TP3=4R採用後、旧設定113.0/35.0/53.4よりさらに悪化）。
   改善ループ第4試行でブレイク検出閾値N・ZigZag閾値・カレンダー窓を緩和する感度分析を行ったが、
   いずれもトレード品質（最大連続損失・ペイオフ比・スプレッドコスト倍率）を犠牲にする明確な
   トレードオフを示し、有効な解消策は見つかっていない。
3. **Validation期間の弱さ**: 3期間中もっともKPI達成数が低い(2/10)。月次シャープ・月次期待値が
   ともに負であり、上記1の地政学ショック混入の影響を強く受けている。
4. **統計的有意性が示せていない**: permutation p値が全期間で0.39〜0.47と高く、観測された正の
   平均リターンが偶然でないとは主張できない。4通貨の相関構造（JPYクロス間の高相関）により
   permutation testの帰無分布が離散的（最大32通り）で分解能が粗いという測定上の制約も影響している。
5. **ペイオフレシオが3期間とも1.0近辺**: TP3=4Rへの引き上げ後もペイオフレシオは1.0前後（Train1.01・
   Validation0.90・Test1.01）でK4m基準(≥1.5)には遠く届かない。段階利確方式自体の設計を見直す余地が
   あるか未検証。
6. **`entry_seq=1`（初回エントリー）のSL率の高さへの有効な対策が未確立**: 除外は不採用と判明したが、
   リスク量の縮小など他のアプローチ（例: 初回エントリーのみリスク%を下げる）は未検証。
7. **重複するトレンドイベントへの対応が不完全**: 1トレンドイベント内の1通貨1ポジションは保証するが、
   同一通貨で別のトレンドイベントが後続して開始した場合の重複は完全には排除しない（§3・§4.5の簡略化）。
8. **`simulate_scaled_scheme`の潜在バグを1件発見・修正済み**（エントリーがH1データの最終バー付近で
   発生した場合のexit_time逆転、2026-08-20修正）。改善ループ第4試行の高頻度化検証で偶然顕在化した
   ものであり、同種の未発見エッジケースが残っている可能性を否定できない。
9. **通貨ペア拡大（GBP/USD等）が未検証**: エントリー機会拡大策として提案した4方策のうち、
   ①②③（検出閾値緩和・ZigZag緩和・カレンダー窓縮小）は検証済みで不採用、④（通貨拡大）は未着手。
10. **K6m（フォワードテストとの乖離率）・K7m（両建て時証拠金消費率）が判定対象外のまま**:
    両建て運用・フォワード検証のいずれも本戦略では未実施。
11. **ZigZag閾値・カレンダーバッファ・TP3水準が暫定値のまま**（§10）: 正式なパーセンタイル導出を
    行えば結果が変わる可能性があるが、改善ループの試行回数制約もあり未着手。

## 12. 総合評価

現時点の正式KPI判定（Train5/10・Validation2/10・Test6/10）は、改善ループの複数回の見直し
（1通貨1ポジション制約、H1継続確認再開、コストモデル精緻化、DD評価方法の是正、通貨絞り込み、
経済指標カレンダーフィルター、エントリー機会拡大の感度分析、エントリー/イグジット診断分析に基づく
TP3引き上げ）を経てもなお、3期間とも過半数のKPI基準を満たせていない。TP3=4Rへの引き上げは月次
シャープ・最大DDを質的に改善したが、KPI達成数そのものは動かず、実効サンプル数はさらに悪化した。
**REJECT相当**の評価が現時点での機械的な結論であり、正式なGO判定には至っていない。司令塔の最終判断待ち。
