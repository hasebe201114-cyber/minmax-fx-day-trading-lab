## 仮説（1行）

**H1のボラティリティ・ブレイク（単発の値幅急変）だけでなく、「H1が構造的にトレンド継続している」という確認（Donchianブレイク等）を検出層に追加することで、SYS-FX011が抱える実効サンプル数不足を、ボラティリティの最低水準フィルターと併用することでトレード当たりの質を大きく損なわずに解消できるのではないか。**

## 検出層の設計（事前登録、結果を見る前に固定）

`00-prescreen.md`の事前診断（診断1: 再開エントリーの質的優位性、診断2: Donchian完全置換は質を悪化させる）を踏まえ、**既存のN_BREAKOUT検出を完全に置き換えるのではなく、追加条件として合成する**設計とする。

H1バー`i`について、以下の**OR条件**でトレンドイベントを検出する（`i`が同時にUP/DOWN両方の条件を満たすことはない。判定順序は明記の通りUP→DOWNの対称ロジック）:

```
range_atr_ratio[i] = (high[i] - low[i]) / ATR(H1, 14, Wilder)[i]
DCU[i], DCL[i] = Donchian(20)（bars[i-20:i]、バーi自身は含まない。indicators.pyのdonchian()既定値をそのまま使用、shift(1)相当）

UP条件  = (range_atr_ratio[i] >= N_BREAKOUT かつ close[i] > open[i])
       OR (close[i] > DCU[i] かつ range_atr_ratio[i] >= CALM_RATIO)

DOWN条件 = (range_atr_ratio[i] >= N_BREAKOUT かつ close[i] < open[i])
       OR (close[i] < DCL[i] かつ range_atr_ratio[i] >= CALM_RATIO)
```

- `N_BREAKOUT = 3.5`（SYS-FX011のTrain導出値をそのまま流用、**再導出しない**）
- `CALM_RATIO = 2.0`（`price_shock_filter.py`で既に確立済みの定数をそのまま流用。「静穏バー」の閾値を「継続イベントとして受理する最低ボラティリティ」に転用する。**本EXP用に新規調整する自由パラメータではない**）
- `DONCHIAN_LENGTH = 20`（`indicators.py`の`donchian()`既定値をそのまま流用）

**この設計により新規に導入する自由パラメータはゼロ**（すべて既存コードベースで確立済みの定数の組み合わせ）。これは診断2の「単純な検出層置き換えは質を悪化させる」という負の所見を踏まえ、(a) N_BREAKOUT単独で捉えていた既知の良質な母集団をそのまま温存し、(b) 継続シグナル（Donchian）による追加候補には「静穏でない（CALM_RATIO以上）」という質フィルターを課すことで、診断2で観測された希釈を抑制する狙い。

イベント検出後は`select_non_overlapping_breakout_events()`（重複除去、72h窓、SYS-FX011と同一）を適用する。

### 解釈（正直な記録）

**必須ゲートの達成数はむしろ悪化した（6/9→5/9）。** 実効サンプル数・permutation有意性・月次シャープは大幅に改善したが、これらはベースラインの時点で既に「必須」達成済みだった項目であり、実質的な効果はなかった。一方、**最大DD（月間）が新たに「年間」も含めて未達に転じ**（月間のみ未達→月間・年間とも未達）、既に未達だったペイオフレシオ（1.087→1.005、建値付近まで悪化）・スプレッドコスト倍率（2.28→1.72、悪化）は改善しなかった。

原因分析: `00-prescreen.md`の診断2（Donchian完全置換）で観測された「n増加⇔質低下」のトレードオフが、OR合成でもほぼ同じ形で再現された。CALM_RATIO（2.0）による質フィルターは診断2の全置換（フィルターなし）よりは緩和的に効いている可能性があるが（イベント数はDonchian単独792件に対し451件に抑制）、それでも追加された約1600件のDonchian由来トレードが、既存524件の質を大きく薄めるには十分な規模だった。改善ループ第4試行（SYS-FX011、N/ZigZag/カレンダー窓の緩和でn増加を狙うも質が一貫して悪化）と同じパターンが、検出層を変えても再現した形になる。

**改善ループ第1試行（`PJ000004`「Q10」上限5回のうち1回目）として記録。** 司令塔判断待ち: (a) CALM_RATIOをより厳しい値に引き上げる再試行、(b) OR合成をやめてAND合成（Donchian継続かつN_BREAKOUT級の高ボラも同時に満たす、イベント数はごく少なくなる見込み）を試す、(c) 本設計の方向性自体を再検討する、のいずれで進めるか。
