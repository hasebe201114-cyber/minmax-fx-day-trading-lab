## 仮説（1 行）

5 通貨ペア × 3 レイヤ MTF（LT=D1/W1 方向 / MT=H4/H1 レンジ+ブレイク強度 / ST=M15/M5 戻り確認）の組み合わせで、長期方向一致 + 中期レンジブレイク（Donchian/BB + S/R ラインの 2 サブ条件 (v2.1 で MT-3 を恒久フォールバック)）+ 短期戻り確認の合計 **4 条件 AND** でエントリーし、レンジ内では両建てで刈り取る戦略は、5 年バックテストで月次シャープ ≥ 0.4・月間 DD ≤ 10%・PF ≥ 1.2 を達成できる。

## 採用 / 不採用の数値基準（試算前に確定）

### 採用条件（全て満たすこと）
- **月次シャープレシオ** ≥ 0.4（5 年平均）
- **月次 Profit Factor** ≥ 1.2
- **月次期待値** > 0 円
- **月間最大 DD** ≤ 10%
- **年間最大 DD** ≤ 20%
- **ペイオフレシオ** ≥ 1.5
- **最大連続損失** ≤ 5 トレード
- **両建て状態の最大証拠金消費率** ≤ 30%
- **バックテスト ↔ フォワードテスト乖離率** ≤ 30%
- **permutation p 値** < 0.05
- **有効サンプル数** ≥ 60 トレード（5 通貨 × 5 年 × 3-4 シグナル/年、MT 強化で減少）
- **弱いブレイクの排除率** ≥ 30%（v2 拡張で追加）

### 不採用条件（1 つでも該当）
- 上記採用条件のいずれかを満たさない
- 確認不足で再現不能（HARKing 疑い）
- false breakout 比率 > 50%（4 条件 AND の意義が失われる、v2.1 で MT-3 恒久フォールバック化により 5→4 条件）
- 通貨ペアの 60% 以上で PF < 1.0（汎用性の欠如）
- MT-2 (S/R ライン) が常に満たせない（= データが機能していない、v2.1 で MT-3 は恒久フォールバック済みのため本条件からは除外）

### フォワードテストの追加条件
- 30/60/90 日の各チェックポイントで採用条件を維持
- 月次で KPI を計測、3 ヶ月連続未達で C 品質チームが保留判定

### 今後の試行回数上限（本追記時点で確定）

1. **追加で試行可能なプリセット/パラメータ候補数は残り最大 3 件**（`scripts/run_train_val_test.py` の `PRESETS` に定義済みの A1_SL_TP / A2_Donchian50 / A3_ADX30、または新規定義する候補を含めて 3 件まで）。
2. 探索は必ず **Train 期間のみ**で行う。Validation / Test は、Train 上で最も spec 基準に近かった候補が 1 つに絞られた後に**それぞれ 1 回だけ**触れる（spec §採用/確認プロトコルの「再学習しない」原則を厳守）。
3. 3 件を使い切った時点で Train 条件を満たす候補が 0 件の場合、**SYS-FX007（現行の LT+MT-1+MT-2+ST 4 条件 AND 構造）はパラメータ調整では改善不可能と判断し REJECT 確定**とする。この場合の次の一手は同一構造でのパラメータ再探索ではなく、エントリー条件の構造そのものの見直し（SYS-FX008 等の別戦略カテゴリへの転換）とする。
4. **有効サンプル数 n≥60 未達の論点（OBS000007 追記6・OBS000004 論点H）は、上記 3 件の試行枠を消費する前に司令塔判断を得ること。** サンプル数不足はパラメータ調整では解決しない構造的制約（年換算シグナル頻度が spec 前提の 1/3〜1/4）であり、対応方針が決まらないまま追加のプリセット試行を重ねることは、OBS000005 論点 B・D が指摘した「多重比較リスクの増加」を繰り返すだけで根本解決にならない。

### 段階的絞り込み（本節冒頭「パラメータ空間」記載）の扱い

spec が定める「約 800 万通りの全パラメータ空間 → train 上位 0.1% → validation 50 候補 → test 10 候補」という段階的絞り込みは、**本PJでは実施しない**ことをここに明記する（OBS000005 差し戻し4 の代替条項「実施しないなら本PJでは省略し単純な逐次探索を採用すると明示的に修正する」を適用）。

理由:
- 1 セルのバックテストに数分〜十数分を要し、全空間探索は計算コスト上非現実的
- 有効サンプル数が構造的に不足しており、広域探索を行っても多重比較のリスクが増えるだけで統計的な結論の質は上がらない

代わりに、上記「今後の試行回数上限」に定めた**単純な逐次探索（残り最大 3 候補、Train のみで絞り込み）**を正式な代替プロトコルとして採用する。

### 3 候補の選定ルール（v2.4 追記、2026-08-15。結果を見る前に確定）

> 司令塔判断（2026-08-15）: permutation test 実施の結果 15 セル全てで有意差なし（OBS000007 追記7）を受け、対応方針として「②エントリー条件緩和」を選択。以下は残り試行枠 3 件（B1_LooseSR / B2_ShortDonchian / B3_LowerADX、`scripts/run_train_val_test.py` の `PRESETS` に定義）を実行する**前に**確定する選定ルール。実行後にこの節を緩めることは禁止する。

**候補**: A1_A2_combined（現行ベースライン）を土台に、1 軸ずつ緩和した 3 候補。
- B1_LooseSR: MT-2 (S/R ライン) の最小接触回数 3→2
- B2_ShortDonchian: MT-1 (レンジブレイク) の Donchian 期間 50→20
- B3_LowerADX: LT (長期方向) の ADX 閾値 20→15

**ベースライン実測値**（A1_A2_combined、Train 期間・5 通貨プール、OBS000007 追記6/7 のデータより算出）: n_trades=66、permutation p 値=0.932（片側）。

**選定基準（各候補について Train 期間・5 通貨プールで評価、全て満たす候補のみ「選定対象」）**:
1. プールした n_trades が **ベースライン(66)以上**であること（緩和が意図通りシグナル頻度を増やしたことの確認。減少した場合はその軸の緩和が逆方向に効いたと判断し、選定対象から除外）
2. プールした permutation p 値が **0.05 未満**であること（spec 本来の統計的有意性基準をそのまま適用。Train 段階だからといって基準を緩めない）

**選定手順**:
- 上記 1・2 を両方満たす候補が複数ある場合、**permutation p 値が最も小さい候補**を選定する
- 1 件も満たさない場合、**Validation/Test には進まない**。3 件の試行枠を使い切ったことになるため、本節冒頭「今後の試行回数上限」項目3 に従い、**SYS-FX007（現行4条件AND構造）はパラメータ調整では改善不可能と判断**し、司令塔に REJECT 相当の判断を仰ぐ

選定された候補（あれば）は Validation → Test の順で**それぞれ1回だけ**評価し、K1m〜K7m + permutation test の全ゲートで最終判定する。

## 検証範囲

- **通貨ペア**: USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD（OBS000002 案 A）

  - MT = H4 / H1（Donchian(20) / BB(20,2) / ATR(14) + **S/R ライン（DS-1 派生）+ 注文板/センチメント（DS-8、v2.1 で現状未使用、DS-8 利用可能時に拡張）**）
  - ST = M15 / M5（ピンバー / 包み線 / ストキャス RSI ダイバージェンス）

- **コスト前提**:
  - スプレッド: 通貨ペア別（USD/JPY 0.3 銭、EUR/JPY 0.5 銭、GBP/JPY 0.7 銭、AUD/JPY 0.6 銭、EUR/USD 0.3 pip）
  - API 手数料: 0.002%
  - スリッページ: 0.5 pip
  - スワップポイント: 両建て時に正味計算（DS-7）
- **両建て制約**: 同時両建てポジション最大 5 セット、証拠金消費率 ≤ 30%
- **経済指標制約**: DS-3 の ±30 分は新規エントリー禁止
- **通貨相関制約**: 相関 ≥ 0.8 のペアは同時エントリーしない
